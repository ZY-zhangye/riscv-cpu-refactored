# RISC-V CPU 底层架构重构尝试分支

本分支用于在 `main` 最新基线上尝试 CPU 底层架构重构，目标是为后续 FPGA 实现、时序优化和功能扩展建立更清晰、更容易验证的 RTL 结构。

## 分支基线

- 分支名：`codex/low-level-arch-refactor`
- 基线提交：`b89e7ac 添加项目README和FPGA测试资料`
- 基线特征：保留 `main` 当前项目资料、SoC 外设、测试平台和已有 RTL 状态，在此基础上重新组织底层微架构实现。

## 重构目标

本分支以可验证、可综合、可逐步回归为优先级，重点探索以下方向：

- 梳理 CPU 顶层、流水级、访存接口和 SoC 外设之间的边界。
- 降低跨流水级组合控制路径的复杂度，优先处理影响 FPGA 时序的回压、flush、异常和访存控制路径。
- 明确流水线寄存器、ready/valid 握手和 kill/flush 语义，避免隐式组合依赖扩散。
- 保持已有测试入口可用，重构过程中优先保证可仿真、可定位、可回退。
- 为后续 Vivado 综合、implementation 和 bitstream 生成保留稳定的工程入口。

## 初始推进方式

建议按以下顺序推进：

1. 盘点 `rtl/cpu_top` 和 `rtl/my_cpu` 的模块边界、时钟复位、握手和异常/中断路径。
2. 建立最小可运行仿真基线，确认当前 `main` 基线下的可用 testbench 和缺失仿真模型。
3. 逐步拆分或重排关键组合路径，单次改动保持小而可验证。
4. 每次 RTL 改动优先通过 QuestaSim 编译和定向测试，再进入 Vivado 综合/实现。
5. 对时序优化相关改动记录 worst path 来源、修改意图和验证结果。

## 约束

- 本分支用于底层架构实验，不直接承诺兼容之前所有探索分支的 RTL 改动。
- RTL 设计修改优先在外层 `rtl/` 中完成，不直接在 Vivado 工程内部改源文件。
- 遇到编译、仿真或综合错误时先停下来定位，不盲目叠加后续修改。
