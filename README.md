# RISC-V CPU 双发射设计分支

本分支用于在无 cache 的 CPU 基线上开展双发射微架构设计与实现。

## 分支基线

- 分支名：`codex/dual-issue-design`
- 基线提交：`fa7eb0b feat: 添加PLIC/定时器模块及测试平台，配置.gitignore`
- 基线特征：保留当前 SoC 外设、PLIC、定时器、UART、测试平台与五级流水线 CPU；不包含后续 icache、dcache 相关实现。

## 设计目标

双发射版本的目标是在现有五级流水线结构上扩展指令吞吐能力，同时尽量保持接口和测试环境稳定：

- 取指阶段支持一次获取或缓冲两条指令。
- 译码阶段支持双指令译码、相关性检查和发射选择。
- 执行阶段逐步拆分为 lane0/lane1，优先保证整数 ALU 与简单访存路径正确。
- 冒险处理覆盖 RAW、load-use、分支跳转、异常和 CSR 访问等场景。
- 对外存储器接口暂时保持无 cache 基线的直接访问模型，降低初期验证复杂度。

## 初始改造范围

建议按以下顺序推进：

1. 梳理现有 `rtl/cpu_top` 五级流水线信号，确定双发射需要扩展的流水线寄存器字段。
2. 增加取指缓冲或两条指令打包接口，先支持顺序双取指。
3. 增加双译码与同周期相关性检测，不能安全双发射时退化为单发射。
4. 将执行、访存、写回通路扩展为双 lane，并定义结构冲突仲裁策略。
5. 建立最小回归测试：单发射兼容、ALU 双发射、load-use 阻塞、分支 flush、CSR/异常串行化。

## 约束

- 本分支以正确性优先，性能优化放在基本双发射功能稳定之后。
- 初期不引入 cache，避免 cache miss、回填和双发射控制同时耦合。
- 保持现有仿真入口和测试文件尽量可用，必要时只做局部适配。
