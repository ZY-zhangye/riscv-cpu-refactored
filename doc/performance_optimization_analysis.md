# CPU 性能优化分析与后续方案

## 1. 结论与优先级

当前单发射 RV32 核已经完成乘法缩拍和级间 `allowin` 注册化，目标主频为 175 MHz。注册化握手使用一级 skid 保存滞后 ready 多接收的完整内容，RTL 性能基准和基础指令回归均未出现额外 IPC 损失。后续两天内的优化优先级如下：

1. 调整数据 BRAM 的物理组织，在不增加访存拍数的前提下提升主频。
2. 实现 16 项窄栈值缓冲，消除热点中的栈标量 load-use 空泡。
3. 仅在前两项完成后，考虑简化 load 响应捕获路径。

以下访存试验已经证明不值得继续，相关未提交代码已从工作区删除：

- 将完整访存请求和响应路径流水化：主频只能达到约 203.8 MHz，但每次访存净增两拍，无法抵消该负载上的 IPC 损失。
- 从新加拍的存储器响应直接组合前递到 EX：重新形成长数据路径，不能在 175 MHz 下收敛。

当前应保留标准的“一拍 load-use stall + 注册后的 MEM 到 EX 前递”。

`allowin` 注册化的整机主频收益仍需重新综合确认。若主频没有改善，该改动至少已经通过功能和 IPC 回归，不应再叠加额外的级间拍数。

## 2. 基线与证据边界

### 2.1 动态计数参考

同一 `irom-v2` 程序在 L3K 上的计数如下：

| 指标 | 数值 | 周期占比 |
| --- | ---: | ---: |
| cycle | 507,616,601 | 100.00% |
| instret | 380,344,383 | - |
| IPC | 0.7493 | - |
| load-use | 121,299,588 | 23.90% |
| execute stall | 63,744,348 | 12.56% |
| branch | 10,958,988 | - |
| branch mispredict | 133,110 | 1.21% 的分支 |

这些计数来自 L3K，不是当前单发核的精确周期结果，只用于识别工作负载特征。完成乘法缩拍后，必须重新跑单发核性能测试作为最终基线。

### 2.2 静态指令特征

`irom-v2` 共 2,216 条静态指令：

- Load 341 条，占 15.39%，其中 `LW` 328 条。
- 紧邻 load-use 194 组，占全部 load 的 56.89%。
- 两条指令内使用 load 结果的有 243 组，占全部 load 的 71.26%。
- 201/328 条 `LW` 以 `sp` 或 `s0` 为基址。
- 85/194 组静态紧邻依赖来自栈 `LW`。

### 2.3 动态热点

程序的主要运行时间位于两个矩阵内核，每个内核执行 10 次：

- `0x980-0xab8`，80^3 内层为 `0x9b8-0xa3c`。
- `0xabc-0xcf4`，转置阶段为 `0xb14-0xbb0`，80^3 乘法内层为 `0xbd0-0xc64`。

第一个内层每次迭代有 8 个可由窄栈缓冲覆盖的立即 load-use，第二个内层有 6 个，因此结构上限为：

```text
10 * 80^3 * (8 + 6) = 71,680,000 cycles
```

加上中外层的标量访问，上限约为 72.5M 拍。考虑实现限制和 L3K/单发核口径差异，保守目标是回收 60-70M 拍，对 507.6M 周期参考基线约等效于 13%-16% 的固定频率吞吐提升。

## 3. 当前时序瓶颈

关闭 live LW 前递后，175 MHz post-route WNS 为 `+0.010 ns`。最差路径为：

```text
RAMB36 数据输出
  -> Block Memory Generator 深度 bank MUX
  -> 外设返回 MUX
  -> MEM load/结果选择
  -> EX 前递数据捕获寄存器
```

该路径延迟为 `5.522 ns`，包含 8 级逻辑，其中布线延迟为 3.230 ns。当前数据 RAM 是单个 65,536 x 32 BMG：

- 容量 256 KiB；
- 64 个 RAMB36；
- 支持 4 路 byte write enable；
- `Algorithm=Minimum_Area`；
- 无 BRAM 输出寄存器。

原始 live LW 路径在 175 MHz 下的 WNS 为 `-2.165 ns`，BRAM 到 EX 的数据路径为 `7.694 ns`。因此不能再次把 BRAM 响应组合接入消费者 ALU。

## 4. 方案 A：四 byte-lane 数据 RAM

### 4.1 结构

将单个 65,536 x 32 BMG 拆为四个 65,536 x 8 byte lane：

- 四个 lane 共用地址和时钟。
- 每个 lane 使用独立写使能。
- 每个 lane 设置 `Fixed_Primitives=16kx1`。
- 四路输出拼接成 32 位读数据。
- 将原始初始化镜像拆成四个 byte-lane 初始化文件。

开启 byte write enable 的 32 位 BMG 不能直接选择 `16kx1`。拆成四个 8 位 lane 后可保持原有字节写语义，同时使用更浅的物理组织。

### 4.2 模块级实验结果

Vivado 2023.2、`xc7k325tffg900-2` 上的模块级 post-route 探针结果为：

| 项目 | 结果 |
| --- | ---: |
| 总 RAMB36 | 64 |
| RAM 输出 MUX 使用的 fabric LUT | 0 |
| 测试频率 | 250 MHz |
| RAMB36 到消费者寄存器路径 | 2.932 ns |
| 该路径 slack | +0.708 ns |

这是模块级结果，不能直接等同于整机主频，但它证明当前深度 bank MUX 可以在不增加 BRAM 数量和访存拍数的情况下消除。结合完整访存流水化试验暴露出的其他路径，整机合理目标为 195-205 MHz。

### 4.3 验收与停止条件

只有同时满足以下条件才保留该方案：

- 单拍读取、byte write 和初始化内容通过回归。
- `irom-v2` 的最终 LED/SEG 输出保持不变。
- 完整 post-route 至少达到 195 MHz。
- load、store 和 load-use 均不新增周期。
- BRAM 使用量仍为 64 个 RAMB36。

如果完整布局布线仍低于 185 MHz，应直接放弃，不在第二天继续做 placement 微调。

## 5. 方案 B：16 项窄栈值缓冲

### 5.1 设计范围

该缓冲只服务编译器溢出到栈上的标量，不做通用数据 cache。推荐初始结构：

- 16 项 direct-mapped。
- `index = address[5:2]`。
- 完整地址 tag、valid 和 32 位 data。
- 仅对以 `sp`/`s0` 为基址的对齐 `SW` 分配。
- 仅允许以 `sp`/`s0` 为基址的对齐 `LW` 查询命中。
- load miss 不分配，避免普通数组和 25.6 KiB 栈内 scratch 污染。
- 主 BRAM 保持 write-through，是架构状态的权威副本。

16 项已经能让热点标量槽位互不冲突。扩展到 32 项无法解决 scratch 容量污染，只会增加查询代价。

### 5.2 一致性要求

所有 store 都必须 snoop 对应 index，而不只是 `sp`/`s0` store：

- 全字 store 命中相同 tag 时更新缓存项。
- 部分 store 或不支持的同地址写入命中时使该项失效。
- MMIO 地址不能分配。

这样可以避免同一栈地址通过其他基址寄存器访问时返回旧数据。

### 5.3 流水时序

命中数据必须经过寄存器，不能组合穿入 ALU：

1. `LW` 位于 EX 时计算地址并查询缓冲。
2. 命中数据在 load 离开 EX 的同一边沿写入专用前递寄存器。
3. 下一条指令进入 EX，并从该寄存器 Q 端取得数据。

第一版只允许普通整数 ALU 消费者零空泡通过。新增时序风险主要是 `EX 地址 -> tag compare -> ID hazard` 的一位控制路径，因此必须先做模块级综合，再接入整机。

### 5.4 验收条件

- 独立查询与捕获模块能在 200 MHz 以上收敛。
- hit、miss、别名、部分写、reset 和 flush 定向测试全部通过。
- 单发核性能测试至少减少 30M 周期。
- 完整 post-route 时序不差于方案 A 的基线。

## 6. 可选后续：简化 load 响应捕获

若方案 A 后最差路径仍终止于 EX 前递或 WB 捕获寄存器，可以把 load 数据从通用 skid/握手数据 MUX 中拆出，在同一个响应边沿无条件捕获。该寄存器必须替换旧捕获路径，不能在其前面再增加一级。

可考虑：

- 原始 `LW` 数据与 valid/目的寄存器元数据分开寄存。
- WB 和标准一拍 stall 后的 MEM 到 EX 前递共用该数据寄存器 Q。
- 必要时让少量 `LB/LH/LBU/LHU` 使用更慢的格式化路径；静态 341 条 load 中有 328 条是 `LW`。

该改动的正确性范围大于 BRAM 物理组织调整，只应在方案 A 完整 route 后进行。

## 7. 暂不投入的方向

### 7.1 JALR 和 RAS

静态 118 条 `JALR` 中有 117 条是返回，但热点只执行约 50 次 return。按每次失预测 3 拍计算，RAS 在热点中最多节省约 150 拍。即使把参考计数中的 133,110 次分支失预测全部消除，也只节省 399,330 拍，占总周期约 0.079%。

当前 BTB 已是 128 项并采用同步查询，不再投入 JALR BTB、RAS 或 loop predictor。

### 7.2 除法器

`DIV/DIVU/REM/REMU` 共 16 条，只位于一次性 ISA 自测，不在矩阵热点中，优化收益低于一千拍。

### 7.3 扩大 live load 前递

将 live 前递扩展到 branch、store 或 JALR 会把 BRAM 数据重新接入跳转、地址和写数据路径，而静态新增覆盖很少，不应继续。

### 7.4 非阻塞乘法

两个热点中都存在 `MUL` 后插入一条独立 `LW`、再使用乘法结果的序列。理论上可隐藏约 10.24M 个周期，但需要 scoreboard、写回仲裁以及完整的 flush/异常处理，两天内风险过高。

## 8. 两天执行顺序

1. 重新测量乘法缩拍和 `allowin` 注册化后的单发核周期与 175 MHz 时序基线。
2. 实现四个 8 位 DRAM lane 并完成模块回归。
3. 只跑一次完整实现，按 185/195 MHz 停止条件决定保留或放弃。
4. 对 16 项窄栈值缓冲先做模块级时序原型。
5. 时序通过后再集成，运行定向测试和 `irom-v2` 性能测试。
6. 仅对同时减少周期且保持时序的配置运行最终完整实现。
