# 面向工业应用的可扩展 RV32 RISC-V CPU 设计、验证与测评报告

## 摘要

本项目完成了一款面向 FPGA 原型验证的 RV32 RISC-V 单发射五级流水 CPU 及配套 SoC 系统。处理器以 RV32I 为基础，支持 RV32M、机器模式 CSR、异常与外部中断，并集成 UART、Timer、PLIC、GPIO/MMIO、片上指令/数据存储器和性能计数接口。为兼顾性能与 FPGA 时序，设计采用级间注册化握手、分支预测、受控 `LW` 旁路、分段乘法流水和 16 项窄栈值缓冲等机制。

验证采用“模块定向测试—ISA 回归—SoC 仿真—裸机程序—FPGA 板级”的分层方法。当前保留的回归日志包含 49 项通过用例：RV32UI 37 项、机器态/CSR 相关 4 项、RV32M 8 项。自建 RTL 性能基准完成并通过 `sink` 校验，综合 CPI 为 1.046。针对 `irom-v2` 热点栈访问，16 项窄栈值缓冲实测减少 73,540,860 个周期，周期数下降 14.96%。

本报告中的官方程序、RT-Thread 和最终实验箱结果仍须在候选 RTL 定版后补测；其余数据均明确标注测试环境和适用边界。

## 1. 项目目标与总体方案

### 1.1 设计目标

项目目标是在 FPGA 上形成可运行、可验证、可测评并可继续演进的 RISC-V CPU 原型，满足以下工程要求：

1. 支持 RV32I 基础指令集，并具备乘除法、CSR、异常与中断处理能力。
2. 构建从 CPU 内核、SoC 外设到裸机软件和性能计数器的完整执行链路。
3. 在功能正确的前提下，围绕流水线冒险、乘法路径和热点访存开展可量化优化。
4. 为官方工业程序和 RT-Thread 测评保留软件接口、外设和性能采集基础。

### 1.2 SoC 总体架构

```text
裸机程序 / 性能基准
          │
    RV32 RISC-V CPU
 IF ─ ID ─ EXE ─ MEM ─ WB
          │
      访问桥与地址译码
  ┌───────┼─────────┬─────────┬───────┐
 指令 RAM 数据 RAM  UART     Timer   PLIC / GPIO
```

CPU 核通过分离的取指和数据访问接口与片上存储系统交互。SoC 顶层提供串口通信、定时器、平台级中断控制器、LED/按键/数码管等 MMIO 外设，支持裸机 C 程序加载、串口输出和板级状态观测。

## 2. CPU 微架构设计

### 2.1 五级流水与控制机制

核心采用经典单发射五级流水结构：

| 阶段 | 主要职责 |
|---|---|
| IF | PC 维护、同步取指、分支预测查询、异常/跳转重定向 |
| ID | 指令译码、寄存器读取、立即数生成、前递选择和冒险判断 |
| EXE | 整数 ALU、乘除法、访存地址、分支判定、CSR 写数据生成 |
| MEM | Load 数据对齐与扩展、异常检查、MEM/WB 结果传递 |
| WB | 通用寄存器和浮点寄存器写回、提交相关接口 |

各级之间通过 `allowin`/`valid` 握手传递数据。跨级反压路径采用注册化处理，并以一级 skid 暂存滞后反压时已接收的完整流水内容，从而避免下游短暂停顿在同周期跨越多个流水级形成长组合 ready 链。

### 2.2 指令集、异常与分支预测

| 能力 | 设计说明 |
|---|---|
| RV32I | 算术逻辑、移位、比较、访存、分支跳转、立即数和地址生成 |
| RV32M | `mul/mulh/mulhu/mulhsu/div/divu/rem/remu` |
| 机器模式 | CSR 访问、`ecall`、`ebreak`、`mret`、异常入口与返回 |
| Z 扩展 | 已配置 Zba、Zbb、Zbkb、Zbs 的部分位操作指令回归 |
| 分支预测 | 128 项 BTB、2 位饱和计数器、目标地址与标签匹配；JALR 不写入预测表 |

取指阶段命中 BTB 且计数器预测跳转时，直接采用预测目标 PC；分支在 EXE 阶段解析。预测错误、异常或中断发生时，流水线清除错误路径并重定向至正确入口。

### 2.3 乘法模块设计

乘法器将 32 位操作数分解为四个 `16×16` 部分积：`LL`、`LH`、`HL` 和 `HH`。四路部分积带有 DSP 使用约束，可并行映射到 FPGA 的乘法资源；随后通过交叉项累加构造低位和高位结果。

| 结果类型 | 数据路径与时序 |
|---|---|
| `MUL` | 低 32 位与操作数符号无关，固定两拍完成 |
| `MULH/MULHSU/MULHU` | 在交叉项累加基础上进行高位符号修正；高位流水深度可配置，当前为三级 |
| 结果提交 | `busy/done/result_ready` 握手保持结果；流水冲刷可取消在途乘法 |

相较于将完整 32 位乘法直接放入关键组合路径，该结构把部分积计算和高位汇总分开，使高位乘法路径具备明确的流水边界。除法与余数采用独立的多周期握手路径，并处理除零和有符号溢出等特殊情况。

### 2.4 load-use 冒险处理与栈值缓冲

普通流水线中，`LW` 的数据在存储器响应后才可供下一条指令使用，因此 `LW→消费者` 紧邻依赖可能产生停顿。项目采用“受控 BRAM 旁路 + 窄栈值缓冲”的分层处理方式。

**受控 BRAM 旁路。** 综合配置默认启用 `LW_LIVE_BYPASS_ENABLE`。当 `LW` 访问固定一拍存储器、EXE→MEM 交接成功、下游无阻塞且下一条为普通整数 ALU 指令时，BRAM 返回数据经专用选择路径前递至 ALU 操作数 MUX。该路径仅覆盖 `LW→普通整数 ALU`，不扩展到分支、Store、JALR、CSR、乘除法、FPU 或位操作等时序敏感消费者；范围外场景继续按常规冒险控制停顿。

**16 项窄栈值缓冲。** 程序热点中大量紧邻依赖来自以 `sp`/`s0` 为基址的栈标量访问。栈值缓冲不是通用 Cache，而是一个 16 项直接映射的 `{valid, tag, data}` 表：

- 索引为 `address[5:2]`，仅服务固定 DRAM 窗口中的对齐字访问。
- 对齐全字栈 `SW` 可分配并更新表项，主 BRAM 同时 write-through，仍是架构状态的权威副本。
- 所有 Store 监听对应表项；全字写更新命中项，部分写或不支持写入使命中项失效，防止别名读到旧值。
- 栈 `LW` 命中后，数据先捕获至专用前递寄存器；下一条普通整数 ALU 从寄存器 Q 端取数，不让 BRAM 返回数据直接组合进入 ALU。
- 未命中或不满足消费者限制时，仍回退到原有 load-use 停顿与通用 MEM→EX 前递。

这种设计将性能优化约束在可验证的热点范围内，同时保持存储器一致性和流水时序边界。

## 3. 功能验证报告

### 3.1 验证环境与流程

RTL 使用 SystemVerilog 编写，仿真日志记录的工具为 Questa Sim 2024.1。验证入口为 `run_all.bat` 和 `run_perf_bench.ps1`，测试镜像位于 `hex/riscv-tests/`。

```text
模块定向自检
      ↓
ISA 指令回归（tb_my_cpu）
      ↓
CPU/SoC 集成仿真
      ↓
裸机基准（tb_top）
      ↓
FPGA 板级运行与串口/LED 观测
```

回归脚本为每项镜像启动仿真，并检索输出中的 `Test passed.`。未找到该标记即判定该项失败，避免只因 RTL 编译通过而误判功能正确。

### 3.2 ISA 回归结果

当前 `results/` 目录保留的 ISA 结果文件中，共有 49 项带有 `Test passed.` 标记的通过用例。

| 类别 | 覆盖范围 | 通过数 |
|---|---|---:|
| RV32UI | 整数算术、逻辑、移位、比较、访存、分支跳转、立即数 | 37 / 37 |
| RV32MI | CSR、`ecall`、`ebreak`、取指异常相关 | 4 / 4 |
| RV32UM | 乘法、除法和余数指令 | 8 / 8 |
| 合计 | 已归档的当前结果 | **49 / 49** |

`run_all.bat` 还配置了 Zba、Zbb、Zbkb 和 Zbs 的回归列表。竞赛提交前需在定版 RTL 上执行 `run_all.bat all`，重新归档 Z 扩展结果，避免使用历史日志替代最终版本的功能证据。

### 3.3 定向测试覆盖

| 测试平台 | 关键检查点 |
|---|---|
| `tb_UART.sv` | UART 寄存器、收发数据与状态 |

### 3.4 系统级功能证据

`results/perf_bench.log` 以 `[PERF] PASS` 结束，表明裸机镜像构建、RTL 编译、SoC 执行、邮箱读取和 `sink` 校验均完成。毕业论文阶段还保留了 UART、Timer、PLIC 波形图、开发板连接图、串口输出和 CoreMark 截图；竞赛正式提交应补采与定版 RTL 和官方实验箱一一对应的照片、终端日志及演示视频。

## 4. 性能测评报告

### 4.1 自建 RTL 性能基准

性能基准位于 `riscv_sim_perf_bench/`，通过 CSR/邮箱输出 `cycles`、`instret`、`CPI(x1000)` 和 `sink`。负载分为 ALU、BRANCH 和 MEMORY 三类，用于分别观察整数吞吐、控制流恢复和访存相关开销。

```text
CPI = cycles / instret
CPI(x1000) = round(1000 × cycles / instret)
```

最新 `results/perf_bench.log` 中的 RTL 仿真结果如下：

| 负载 | cycles | instret | CPI |
|---|---:|---:|---:|
| ALU | 216,022 | 216,011 | 1.000 |
| BRANCH | 274,402 | 227,026 | 1.208 |
| MEMORY | 601,795 | 600,869 | 1.001 |
| OVERALL | **1,092,219** | **1,043,906** | **1.046** |

该次测试的 `sink` 为 `f5b4d4ae`，且日志给出 `[PERF] PASS`。ALU 和 MEMORY 负载接近单周期吞吐，BRANCH 的 CPI 较高，反映分支预测失败和重定向仍有可优化空间。该结果只适用于当前自建程序、镜像和 RTL 仿真环境，不能直接替代官方程序得分。

### 4.2 栈值缓冲优化结果

对 `irom-v2` 工作负载的静态分析显示：2,216 条静态指令中有 341 条 Load，其中 194 组为紧邻 load-use 依赖；85 组来自栈 `LW`。因此选择以栈值缓冲覆盖高频标量访问，而非引入通用数据 Cache。

| 指标 | 结果 |
|---|---:|
| 优化后 CPU 周期 | 418,184,261 |
| 实际零空泡 ALU 前递次数 | 73,540,860 |
| 周期减少 | 14.96% |

该结果表明窄栈值缓冲的优化方向与负载热点匹配。性能数字来自对应的 `irom-v2` 测试口径；不同程序、不同频率或不同版本间的对比必须统一镜像、配置和计数口径。

### 4.3 时序与资源权衡

当前设计主要受 BRAM 读取、数据选择、前递捕获及其布线影响。性能优化实验得到以下结论：

| 方案 | 结果 | 结论 |
|---|---|---|
| 四 byte-lane 数据 RAM | 200 MHz post-route WNS `-0.674 ns`，等效约 176.2 MHz | 未达到停止线，已放弃 |
| 16 项栈值缓冲 | 高 QoR + post-route physopt WNS `-0.054 ns`，等效约 173.4 MHz | 保留，吞吐相对 175 MHz 无栈缓冲基线约提升 16.5% |
| 独立 load 响应寄存 | 可在受限场景达到 +0.054 ns，但 `irom-v2` 增加 31,950,572 个周期 | 时序收益不足以抵消 IPC 损失，已放弃 |

因此，当前优化策略以保持高 IPC 为主：保留受控 `LW` 旁路和窄栈值缓冲，不扩大高扇出 BRAM 数据旁路范围；继续针对 EX payload CE 和 DRAM 写使能等局部控制路径进行物理优化。最终提交前仍需以目标实验箱的 post-route 报告确认时序、资源和频率。

## 5. 提交前补测计划

1. 固定候选 RTL 的 Git 提交号和综合配置，记录目标 FPGA、工具版本与时钟约束。
2. 执行 `run_all.bat all`，归档 RV32I、机器态、M 和已实现 Z 扩展的全量结果。
3. 单独执行 UART、Timer、PLIC、BTB、乘法、除法、BRAM 旁路和栈值缓冲测试，保存断言通过日志与关键波形。
4. 在竞赛实验箱上重新运行官方工业程序，采集下载过程、串口输出、性能计数和演示视频。
5. 完成 RT-Thread 启动、中断、串口、定时器和任务调度验证，并按统一口径输出性能数据。
6. 对每一项性能优化，坚持“功能回归通过后再比较性能”的顺序；不将不同镜像或不同配置的结果直接比较。

## 6. 结论

本项目已形成从 RV32 CPU 内核、SoC 外设、裸机软件到自动化仿真和性能计数的工程闭环。五级流水、128 项 BTB、分段乘法流水、受控 BRAM `LW` 旁路与 16 项窄栈值缓冲共同构成当前微架构的主要性能设计。现有 ISA 回归和 RTL 基准已提供功能与性能证据，栈值缓冲在目标热点上取得了明确的周期收益。

下一阶段的重点是完成实验箱时序收敛、官方工业程序及 RT-Thread 测评，并以可复现的原始日志、资源报告和演示视频形成竞赛最终提交材料。
