# 从顺序 RV32 核到最小 Linux 系统

## 目标与边界

目标系统是 Zynq-7020 PL 中的自研 RV32 核，运行启用 MMU 的 Linux，以串口为控制台、initramfs 为根文件系统，执行 `/init` 并能重复处理定时器中断和用户态系统调用。ARM PS 用于提供 DDR、系统初始化与下载支持；在 ARM 上启动 Linux 不算完成此目标。

以单核、顺序单发、RV32IMA + Zicsr + Zifencei、M/S/U 特权级和 Sv32 为目标基线。不要求 FPU、压缩指令、双发、乱序、SMP、块设备或网络。软件构建必须匹配实际实现的 ISA，采用无浮点依赖的 RV32 ABI；选定 Linux 版本后，核对其 Kconfig、工具链与扩展最低要求，不直接沿用桌面发行版配置。

核心路线是先建立正确性，再逐层扩展地址空间、权限和系统软件。每一步保留上一阶段的回归，新增行为有独立验收条件。全程不以旧时序报告或文件名判定已经实现某项能力。

## 接续开发基线

工作区为 `W:\riscv-cpu-refactored`，沿用公开仓库 `ZY-zhangye/riscv-cpu-refactored`。开发分支 `dev/linux-bringup` 从 `main` 的 `d78188fa64b86977d0ce9cb570d3ced46ca0119c` 切出。这个 main 是集创赛收官版，包含寄存器化反压、边界 skid buffer、栈值缓冲与独立 RV32M IP，和旧毕业设计 `project2` 同源但并非相同 RTL。

保留原目录、`run_all.bat`、测试台和 HEX，不把刚才 F 盘迁移版的 RTL 或仿真模型覆盖进来。此前针对 F 盘 project2 的测试结论不适用于此分支；本分支以自身的回归结果为准。

原脚本默认用例总数是 77（UI 37、MI 4、UM 8、Zba 3、Zbb 13、Zbkb 5、Zbs 7）。这里只覆盖脚本列出的指令，未使用整个 HEX 目录宣称完整 ISA 或 Linux 兼容性。Questa 使用 `DEBUG_EN` 的仿真 RAM 和 RTL 乘除法路径；厂商 IP、综合后的 RAM 延迟、FPGA 时序与板级集成仍需另验。

## 现状与主要缺口

| 当前基础 | 到 Linux 的缺口 |
| --- | --- |
| 五级顺序流水线、分支预测、乘除法 | 精确异常、可观察退休事件、完整指令合规性 |
| M 模式 CSR 与异常处理 | S/U 模式、权限检查、异常 / 中断委托、PMP |
| 分离的取指 / 数据 RAM 接口 | 统一物理地址空间、背压、错误返回、可变访问延迟 |
| main 为无 cache 基础版本；另有 cache 分支 | 需基于内存协议重新核对缓存集成、一致性、MMIO 属性与刷新 |
| UART、timer、PLIC | 兼容固件和内核的寄存器语义、IRQ 映射与设备树 |
| 基础及 Z 扩展测试镜像 | A 扩展、特权、页表、异常副作用和系统启动测试 |
| Kintex-7 设计材料 | Zynq-7020 的 PL 时钟、AXI、PS DDR 与板级配置 |

`fpu.sv` 占位不等于 F 扩展可用。当前 `instret` 是估算值，不能据此精确比较 IPC。现有 DEBUG_EN 路径的 Questa 回归是软件功能基线，不等于厂商 IP、时序和真实板卡验证。

## 1. 固定可复现的架构基线

固定 RTL 文件清单、测试镜像、仿真器版本和脚本参数。默认回归明确列出实际执行的用例及结果；迁移时保留的其他 HEX 需要单独分类，不能因文件存在就计入通过数。

在写回 / 退休边界产生明确的指令退休事件，记录 PC、指令、寄存器写入以及访存副作用。`minstret` 依据退休事件递增，异常指令不计入；RV32 的周期与退休计数实现高低半部及相应访问控制，计数值不能靠气泡或分支次数推算。

审查非法指令、CSR 权限、ECALL / EBREAK、取指与访存地址错误、中断和分支冲刷。被取消的指令不得写寄存器、CSR 或外设；较年轻的 store 不能越过较老指令的异常产生不可撤销副作用。同步异常的 PC、原因、`tval` 和返回路径要可预测。

**验收：** 当前默认回归可重复通过；新增用例覆盖流水线中多种异常位置与 IRQ 到达时机；退休日志可与参考 ISA 模型比较；一段无异常程序的退休计数与实际指令数一致。

## 2. 建立统一且支持等待的内存系统接口

Linux 的代码和数据共享同一物理地址空间。当前分离 RAM 形式需要演进为两个请求端口通向统一内存：取指与 load / store 对同一地址看到一致内容，支持自修改代码和页表读取。

定义请求 / 响应协议，包含地址、数据、字节使能、请求类型、完成与错误状态。单个未完成请求也足够作为第一版；必须能够等待任意周期，不能假设 RAM 或 DDR 固定延迟。冲刷发生时区分尚未接受的请求与已接受、仍需收回响应的请求。

统一地址图并划分可缓存 RAM、不可缓存 MMIO 与错误地址。先用仿真 RAM 和延迟注入器完成接口，不必等 AXI 或实际 DDR。

**验收：** 随机延迟与总线错误下回归通过；同址写后读正确；写代码后按规定执行同步指令，取指可见；MMIO 每个事务只生效一次；取消请求不丢失 / 错配响应。

## 3. 补齐 RV32IMA 与内存顺序

先确认现有 I / M / Zicsr 实现边界，修复符号扩展、除零、溢出和 CSR 读改写等细节。`misa` 和其他能力信息应准确反映硬件，不能允许软件写出未实现的扩展。

实现 A 扩展的 LR.W / SC.W 和所需 AMO.W 运算。定义 reservation 的粒度、建立和失效条件；冲突 store、异常 / 上下文切换策略、其他总线主机写入的处理都要有明确约定。SC 成功时返回零并且只写入一次，失败时不写；保证操作的不可分割性。

对单核第一版可保守串行化原子访存和相关 `aq` / `rl` 顺序，之后再优化。实现 `FENCE` 的可观察内存 / I/O 顺序和 Zifencei 的 `FENCE.I`。不要把普通 load / store 直接拼成 AMO；不能只对同一个 CPU 的访问宣称原子，却忽略共享 AXI 内存的其他访问者。

最初可限制 PS 在软核运行期间不写入软核管理的 RAM，关闭其他 DMA；该限制必须成为平台契约。之后接入 DMA 时，增加 reservation 失效、缓存维护或经验证的一致性机制。是否使用 ACP 要结合具体 Zynq 通路验证，不能默认任意 AXI HP 端口与 PL cache 自动一致。

**验收：** ISA 定向 / 参考模型测试通过；LR / SC 成败与 AMO 返回旧值、写入新值正确；冲突写入可使 reservation 失效；RAM 与 MMIO 顺序测试通过。

## 4. 实现特权级与固件契约

依照选定 RISC-V 特权规范版本补齐 M/S/U 状态、CSR 访问权限、`MRET` / `SRET`、ECALL、`WFI` 的正确实现或允许的行为，以及中断使能 / 待决规则。实现 `medeleg` / `mideleg`、`stvec`、`sepc`、`scause`、`stval`、`sscratch`、`satp` 和相关 `mstatus` / `sstatus` 位。

PMP 提供 M 模式到 S/U 模式的物理访问控制，并与 MMU 权限检查配合。为第一版固定允许的 RAM 和外设区域即可，但读写执行权限、匹配与错误行为要符合规范。若采用硬接线平台策略，必须先核对规范与固件要求，不能简单忽略权限检查。

明确定时器、软件中断和外部中断的模式归属。可由 M 固件处理机器定时器并向 S 模式注入定时器中断；PLIC 需要 S 模式上下文或等价的可用路径。优先复用兼容的 SBI 实现；若编写最小 M 固件，按所选 Linux 版本实现它实际需要的 SBI 接口，包括能力探测、定时器和关机 / 复位等契约。

**验收：** M → S → U 切换、陷入与返回测试通过；委托后的异常进入正确处理器；用户态访问特权 CSR 被拒绝；定时器可周期唤醒 S 模式代码；SBI 调用有明确返回值。

## 5. 实现 Sv32 MMU、TLB 和页表遍历

先实现无 TLB 的串行页表遍历，把协议和权限做对，再加入小型取指 / 数据 TLB。支持 Sv32 两级页表、4 KiB 页与合法的 4 MiB 超级页、`satp` 模式及地址空间标识的明确策略。

检查 PTE 合法性与 R/W/X/U、SUM / MXR 等权限，区分取指、load、store 页故障；页表遍历本身的总线错误必须按规范产生正确异常。故障 `tval` 应记录原始故障虚拟地址。对 A / D 位选择规范允许且 Linux 兼容的更新方式；若由硬件更新，更新必须与并发访问保持必要的原子性。

页表遍历器使用物理地址访问内存并接受 PMP 检查；不能递归翻译自己的读取。`SFENCE.VMA` 的地址 / ASID 参数可在初版保守地刷新全部 TLB，但必须保证失效后没有旧映射继续被使用。切换 `satp`、模式切换、分支冲刷和未完成页表请求的交互要纳入测试。

**验收：** bare / Sv32 模式均能运行；测试正常页、超级页、跨页访问、无效 / 只读 / 不可执行页、U/S 权限、A/D 位和页表读取错误；更新页表后执行 `SFENCE.VMA` 能观察新映射；小型 S 模式程序能进入映射后的 U 模式并处理缺页异常。

## 6. 接入 cache 并保持正确可见性

保留无缓存路径作为对照。第一版优先直接映射或小容量组相联、阻塞式 cache，避免同时引入复杂并发。访问属性以平台地址图为准，UART、timer、PLIC 与 AXI 控制寄存器走不可缓存路径。

明确物理索引 / 标签方案与 MMU 集成边界。写直达能简化页表和数据的可见性，但仍需处理等待、写缓冲、I/D cache 分离及其他主机写入。若使用写回，页表遍历器要读到最新页表，不能绕过 dirty D-cache 直接读陈旧 DDR。

`FENCE` 保证所要求的 RAM / MMIO 顺序；`FENCE.I` 等待相关数据写入可见并使取指路径不再使用旧指令。I-cache、D-cache、TLB 和页表遍历是不同机制，应分别明确失效动作。

**验收：** 有 / 无缓存执行结果一致；覆盖命中、未命中、替换、写入字节使能、总线错误和自修改代码；页表更新不会读取旧数据；MMIO 读写次数与程序要求一致。

## 7. 完成 Zynq-7020 的 AXI 与板级集成

通过 AXI 连接 PL CPU 内存系统与 PS DDR，保留 BRAM 启动入口。确认 AXI 地址宽度、突发、字节 strobe、返回码、时钟域、复位和背压；初版使用受限事务和保守性能即可。PS 初始化 DDR，随后把固件、设备树、内核和 initramfs 放入约定位置并释放 PL CPU。

具体开发板型号确定后重建时钟和复位 IP、Zynq PS 配置与 XDC，检查 DDR 可访问窗口、UART 引脚和下载流程。Linux 控制台第一版可继续使用 PL UART；需要为其写驱动或将寄存器接口改为已支持的 UART 模型，设备树必须如实描述，不能直接标成不兼容的 16550。

RAM 容量按选定内核和 initramfs 的真实镜像 / 运行需求规划，不能假定现有 BRAM 足够。初版可以由 PS 辅助加载镜像，启动链稳定后再考虑自主外部存储启动。

**验收：** AXI 仿真覆盖背压 / 错误；板上 DDR 连续读写和地址边界测试通过；现有 CPU 回归代表程序、UART、定时器与异常测试在板上运行；综合和实现报告满足实际设置的时钟约束。

## 8. 打通固件、设备树和最小 Linux

固定工具链、Linux、SBI 固件和用户态工具版本。先用同一设备树和镜像在参考平台验证构建流程，再迁移至自研平台；参考平台成功只说明软件构建合理，并不证明自研硬件正确。

设备树描述 CPU ISA / MMU、RAM 区间、时钟、UART、timer / interrupt-controller、PLIC IRQ 与 `chosen` 控制台配置。固件保留区、内核、DTB 与 initramfs 不得重叠。按 RISC-V Linux 启动 ABI，在入口提供 `a0 = hart ID`、`a1 = DTB 物理地址`，设置约定的特权级、`satp` / 中断状态及内核入口对齐等条件。

内核开启所需 RV32、MMU、串口、IRQ、timer 与 initramfs 支持，关闭首版不需要的子系统；使用实际 UART 的驱动及对应 early console 设置。initramfs 可只含一个静态链接的软浮点 RV32 `/init`，输出标志后执行少量系统调用，不必第一步就搭完整 BusyBox 根文件系统。

把启动过程拆成固件串口 → SBI 调用 → 内核早期输出 → 页表启用 → IRQ / timer → 用户态 `/init`，每个阶段保留可定位的寄存器和陷入日志。

**验收：** 内核在 PL RISC-V 上打印启动日志并执行 `/init`；定时器持续工作；用户态系统调用、调度与缺页处理可运行；复位后重复启动成功。此时再扩展 shell、文件系统或驱动。

## 可选分支与后续实验

无 MMU Linux 可用于练习固件、设备树、驱动和内核裁剪，前提是选定版本确实支持目标 RV32 配置与用户态格式。它仍需要正确的 ISA、原子操作、异常、中断和平台支持，不能仅靠现有 M 模式核直接运行；完成该分支也不代表完成 Sv32 主线。

稳定启动 Linux 后，再通过真实退休计数、cache 命中率和内核负载定位瓶颈，评估分支预测、受限双发与更大缓存。乱序可以另开实验版本研究重命名、ROB 和精确提交；它与 Linux 启动没有直接依赖。FPU 或压缩指令仅在软件生态 / 性能需要时加入，并同步扩展 ISA 宣告、上下文保存和回归。
