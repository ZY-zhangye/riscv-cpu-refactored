# 评委可能提问大纲与答辩要点

适用作品：**基于 RISC-V 指令集的高性能 CPU 实现与回归测试工程**。本文按评委最可能追问的顺序编排；每个问题后的“答题要点”用于组织回答，不要求逐字背诵。

## 一、答辩策略

1. 先给结论，再说明机制，最后给验证或数据支撑。
2. 对“为什么这样设计”，优先从 **FPGA 资源、时序、流水线接口、正确性边界** 四个维度回答。
3. 未在 PPT 或实现报告中固化的资源、频率、功耗数字不要估算；应说明“该项以当前综合报告为准”。
4. 遇到细节追问时，始终强调：主存 / BRAM 是架构状态，优化结构不能破坏软件可见语义。

## 二、高优先级：乘法模块

### 1. 为什么不直接使用 `*`，而是拆成四个 16×16 部分积？

**答题要点：**

- 目标是让综合器更明确地映射到 FPGA DSP 乘法资源，避免形成难以控制的长组合路径。
- 32 位乘法拆成 LL、LH、HL、HH 四个 16×16 部分积，可并行计算，再进行交叉项累加。
- 该结构同时适用于低 32 位乘法和高 32 位乘法，硬件复用度更高。

### 2. `MUL` 与 `MULH/MULHSU/MULHU` 为什么采用不同的流水级数？

**答题要点：**

- `MUL` 只需要低 32 位，结果路径较短，固定两拍完成。
- 高位乘法还要处理交叉项和符号修正，当前配置采用三级流水以缩短关键路径。
- 这是在吞吐、延迟和时序之间的折中，而不是功能差异。

### 3. 有符号、无符号和混合有符号乘法如何共用一套硬件？

**答题要点：**

- 四个部分积先按统一数据通路计算；低 32 位结果对不同符号形式可直接复用。
- 符号差异主要影响高 32 位，因此在高位结果阶段进行符号修正。
- 这样避免为每种乘法指令重复配置完整乘法器。

### 4. 多周期乘法如何避免阻塞或错误写回？

**答题要点：**

- 模块具有输入锁存、忙状态和结果有效控制；结果未准备好时流水线按握手协议等待。
- 下游背压时结果保持不变；发生冲刷时取消该次未提交计算，避免错误路径写回。
- 验证已覆盖符号边界、随机向量、流水冲刷和下游背压场景。

### 5. 乘法设计的真正收益是什么？

**答题要点：**

- 重点不是单纯缩短单条指令拍数，而是将乘法关键路径切分为可控流水段。
- 对 FPGA 而言，DSP 资源利用和时序收敛同样重要；该方案为更高主频和稳定综合提供基础。

## 三、高优先级：倒数乘精确除法

### 6. 为什么采用“倒数查表 + 倒数乘法”，而不是传统逐位恢复除法？

**答题要点：**

- 逐位试商通常迭代次数较多，延迟随位宽增长；本设计将除法转换为倒数估计和乘法修正。
- FPGA 对 ROM 和乘法资源较友好，因此利用倒数 ROM 与乘法数据通路可获得较稳定的固定延迟。
- 数据通路中不使用运行时 `/` 或 `%` 运算符，避免依赖不透明的综合推断结果。

### 7. 除法器的计算流程是什么？

**答题要点：**

1. 检查除零、`INT_MIN / -1` 等特殊情况；
2. 对有符号操作取幅值，并用前导零计数归一化除数；
3. 从 65,536 项、40 bit 精度倒数 ROM 读取初始倒数；
4. 执行一次 Goldschmidt 修正，通过乘法重建商；
5. 用最终余数检查并至多校正一次商值，恢复商和余数符号。

### 8. 只进行一次 Goldschmidt 修正，如何保证商和余数精确？

**答题要点：**

- ROM 提供足够精度的初始倒数，归一化使估计区间受控。
- 迭代后不直接把近似结果提交，而是进行“商乘除数”的最终余数检查。
- 若存在边界误差，执行至多一次商值校正，因此最终满足 RV32 的精确 `DIV/DIVU/REM/REMU` 语义。

### 9. 为什么 ROM 要采用 64K 项、40 bit 精度？资源代价是否过高？

**答题要点：**

- 这是为一次迭代后仍保留足够精度、并降低最终校正复杂度所选的折中。
- 该 ROM 是只读、规则且适合映射片上存储资源；具体 BRAM 占用以综合报告为准。
- 设计取舍是“较确定的存储资源”换取“较低且固定的除法延迟”。

### 10. 除零、溢出、余数符号分别如何处理？

**答题要点：**

- 除零和 `INT_MIN / -1` 不进入普通迭代路径，直接按 RISC-V 规范返回结果，延迟为两拍。
- 普通路径延迟为 14 拍；除法和取余共享主计算过程。
- 有符号操作先以幅值计算，最终按被除数和除数的符号恢复商、余数符号。

### 11. 除法器如何与五级流水线连接？

**答题要点：**

- 除法是多周期执行单元，采用请求握手、结果保持和完成信号与流水线交互。
- 结果未完成时不允许其提前写回；下游不能接收时，结果保持有效。
- 冲刷发生时取消未提交除法，保证异常或分支错误路径不会污染架构状态。

### 12. 14 拍延迟是否一定优于 IP 核或逐位除法？

**答题要点：**

- 不能脱离 FPGA 型号、目标频率和资源预算简单比较“绝对更优”。
- 本设计的优势是算法、延迟、接口和验证均可控，并可与自研乘法和流水控制协同优化。
- 若项目后续更重视开发周期或特定器件 QoR，也可将其与厂商 IP 做同条件的综合对比。

## 四、高优先级：栈值缓冲与 load-use 冒险

### 13. 栈值缓冲解决的核心问题是什么？

**答题要点：**

- 程序中有大量以 `sp` 或 `s0` 为基址的栈变量访问，容易形成 `LW → 整数 ALU` 紧邻依赖。
- 常规 BRAM 访存路径中，Load 数据尚未有效时，消费者需要停顿。
- 16 项栈值缓冲命中后将数据送入专用前递寄存器，使下一条普通整数 ALU 指令可零空泡执行。

### 14. 它为什么不是通用 Cache？

**答题要点：**

- 该结构只服务以 `sp/s0` 为基址的对齐栈标量访问，容量固定为 16 项，目的明确且边界可控。
- 主 BRAM 始终是架构状态和最终数据来源；缓冲仅保存热点数据副本，不能改变软件可见存储语义。
- 不将其做成通用 Cache 是为了控制一致性复杂度、资源开销和验证范围。

### 15. 16 项如何组织？发生冲突怎么办？

**答题要点：**

- 缓冲采用直接映射组织，以地址 `address[5:2]` 作为索引，并保存有效位、标签和数据。
- 地址冲突时由新访问覆盖原表项；冲突只影响命中率，不影响正确性。
- 16 项是对热点栈访问收益与硬件成本的折中，后续可通过基准统计评估是否需要扩容或调整相联度。

### 16. Store 后如何保证数据一致性？部分写入如何处理？

**答题要点：**

- 对齐全字栈 Store 可分配或更新缓冲，同时主 BRAM 保持写穿。
- 所有 Store 都对命中表项进行监听；部分写入可能只改变一个字节，无法安全直接复用整字数据，因此使对应表项失效。
- 这样确保缓冲中没有陈旧数据，下一次未命中访问仍由主 BRAM 获取正确值。

### 17. 为什么只让“普通整数 ALU”消费者零空泡？

**答题要点：**

- 分支、Store、CSR、乘除法等消费者的时序和语义边界更复杂，激进旁路会扩大验证范围。
- 设计先覆盖最常见、收益最大的 `LW → 整数 ALU` 热点，再保留其他场景的一拍停顿。
- 这是局部、受控优化：先保证正确性与时序，再扩展覆盖面。

### 18. BRAM 旁路和栈值缓冲是什么关系？

**答题要点：**

- 综合配置中，受控 BRAM 旁路默认开启；它针对固定一拍 BRAM 路径提供直接前递能力。
- 栈值缓冲是更有针对性的热点优化：命中数据先被捕获到专用前递寄存器，降低对 BRAM 返回路径的依赖。
- 两者共同服务于减少 load-use 停顿，但栈值缓冲才是该页优化的主要设计重点。

### 19. 性能收益如何证明？

**答题要点：**

- 在 `irom-v2` 测试中，周期数减少 73,540,860，周期下降 14.96%。
- 该数据应解释为特定程序负载下的实测收益，而非所有应用的固定提升比例。
- 对访存模式不以栈访问为主的程序，收益会降低；这也是后续可继续优化通用访存路径的原因。

## 五、流水线、异常与中断

### 20. 为什么选择单发射五级流水，而不是双发射或乱序？

**答题要点：**

- 作品首先建立一个可验证、可测评、可在 FPGA 稳定运行的处理器原型。
- 单发射五级流水结构清晰，便于扩展指令、CSR、异常中断和外设系统，也便于定位性能瓶颈。
- 双发射、Cache 和 AXI 是在该稳定基线上的后续演进方向。

### 21. 普通 RAW 冒险如何处理？控制冒险如何处理？

**答题要点：**

- 普通 RAW 相关优先使用 EXE、MEM、WB 多级前递。
- 不能安全前递的 load-use 相关按需暂停。
- IF 阶段 BTB 进行分支预测；预测失败、跳转或异常发生时冲刷错误路径指令。

### 22. 注册化握手和暂存缓冲的价值是什么？

**答题要点：**

- 防止多个级之间形成过长的组合反压链路。
- 在多周期乘除法、访存停顿和冲刷同时出现时，令每级接受、保持、清空行为更明确。
- 其主要价值是时序可控性和控制正确性，而非单独提高 IPC。

### 23. 异常与中断为什么要统一进入 Trap 路径？

**答题要点：**

- 同步异常和异步中断来源不同，但都需要保存现场、跳转服务程序并在处理后恢复。
- 统一 Trap 路径可减少重复控制逻辑，并保证 CSR 更新、流水冲刷和 `mret` 恢复遵循同一套规则。

### 24. PLIC 在系统中扮演什么角色？

**答题要点：**

- PLIC 对 Timer、UART 等外部中断源进行仲裁和投递。
- CPU 负责 Trap 入口、CSR 状态维护和服务程序执行；PLIC 负责外部中断管理，两者职责清晰。

## 六、验证、性能与工程化

### 25. 如何证明 CPU “不仅能仿真，而且能运行”？

**答题要点：**

- 模块级验证覆盖 UART、Timer、PLIC 等外设；CPU/SoC 级覆盖指令、乘除法、异常、中断和冒险处理。
- 最终在 FPGA 板级运行裸机程序，通过串口、LED、数码管观察结果。
- 因此验证路径是“模块正确 → CPU 正确 → 系统可运行 → 板级可观测”。

### 26. 性能数据如何采集？CPI 是否可信？

**答题要点：**

- 通过 CSR 性能计数器采集周期数 `Cycle` 和提交指令数 `Instret`，并计算 `CPI = Cycle / Instret`。
- 基准分别覆盖 ALU、分支、访存三类典型负载，综合基准 CPI 为 1.046。
- 数据是当前 RTL 自建基准的结果；应明确它不等同于不同编译选项、不同频率下的通用软件性能结论。

### 27. 为什么分支密集型 CPI 高于其他两类？

**答题要点：**

- 分支预测失误会带来错误路径冲刷和重新取指开销。
- 当前 BTB 已降低控制冒险，但预测器容量、索引冲突和动态分支模式仍会影响命中率。
- 这说明后续分支预测优化是有数据支撑的方向。

### 28. CoreMark 的定位是什么？

**答题要点：**

- 已完成 CoreMark 裸机运行验证，用于证明系统可执行具有代表性的标准计算负载。
- 当前重点是建立测评基础；若比较绝对分数，需要统一时钟、编译器、优化选项、内存配置和运行模式。

### 29. 自动化回归测试的价值是什么？

**答题要点：**

- 指令扩展、流水优化和异常中断之间存在交叉影响，手工测试难以保证每次修改都不引入回归。
- 自动化回归将定向测试、随机向量、冒险、冲刷和外设测试纳入固定流程，提升迭代可信度。

## 九、指令集与总体微架构追问

### 30. 当前 CPU 支持到什么范围？哪些功能不应被表述为已经完整支持？

**答题要点：**

- 已完成 RV32I 基础整数指令、RV32M 乘除法、Zicsr，以及部分 Z 位操作扩展。
- 作品已具备异常中断、性能计数和 SoC 外设运行能力。
- 不应笼统表述为“完整支持所有 RISC-V 扩展”或“已经完成 RT-Thread 官方测评”；RT-Thread 目前是具备移植基础和后续验证方向。

### 31. 为什么选择 RV32，而不是 RV64？

**答题要点：**

- 本项目面向 FPGA 上的嵌入式处理器原型，RV32 的数据通路、寄存器宽度、存储资源和验证规模更适合作为首个完整实现。
- RV32I/M 已覆盖裸机控制、整数计算与常见嵌入式软件需求。
- 位宽升级到 RV64 不只是数据位扩展，还会牵连 ALU、乘除法、访存、CSR、异常和软件工具链，适合在稳定 RV32 基线后进行。

### 32. 为什么采用五级流水？每一级的职责是什么？

**答题要点：**

- IF 负责取指和 BTB 预测；ID 负责译码、读寄存器、生成控制信息并检测相关。
- EXE 负责 ALU、乘除法、分支跳转与地址生成；MEM 负责数据存储访问；WB 负责结果提交。
- 五级划分使功能边界、冒险位置和性能计数点明确，也方便逐步替换或增加执行单元。

### 33. 单发射结构的吞吐上限是什么？

**答题要点：**

- 理想情况下每周期提交一条指令，因此理想 CPI 为 1。
- 实际 CPI 会受到分支预测失误、load-use 相关、多周期运算、异常和访存停顿影响。
- 自建 ALU 基准 CPI 为 1.000，说明主整数数据通路在该负载下已接近单发射理论上限。

### 34. 级间传递哪些信息？为什么要区分控制包和数据包？

**答题要点：**

- 数据包传递源操作数、立即数、PC、预测目标、CSR 数据和访存相关数据；控制包传递功能单元选择、写回选择、写使能、目的寄存器和多周期标记。
- 分包可降低模块耦合：执行单元只消费自身需要的控制和数据，便于扩展新指令或定位控制错误。
- 级间数据统一寄存器化，确保停顿或冲刷时“保持什么、清空什么”可明确描述。

### 35. 译码冲突或非法指令如何处理？

**答题要点：**

- 译码逻辑按 opcode、funct 等字段识别支持指令，并生成唯一的控制组合。
- 对不支持或非法编码，应进入异常 / Trap 处理路径，而不是产生不确定写回。
- 回答时可强调：非法指令测试应与正常指令回归共同执行，防止译码扩展破坏已有控制逻辑。

### 36. 写 x0 如何处理？

**答题要点：**

- RISC-V 规定 x0 恒为零，任何写 x0 的结果都不能对后续可见状态产生影响。
- 写回和前递逻辑均需将 x0 作为特殊边界处理，避免错误前递“非零 x0”。
- 这是寄存器堆、冒险检测和前递测试中必须覆盖的基础用例。

### 37. 为什么没有先做 Cache，而先做栈值缓冲？

**答题要点：**

- Cache 会引入替换、写策略、失效、一致性、异常交互和验证规模等系统性复杂度。
- 栈访问具有基址稳定、局部性强、热点明显的特征；16 项受控缓冲可先解决高频 `LW → ALU` 依赖。
- 该方案以较小硬件和验证代价获得实测收益，同时保留未来加入通用 Cache 的架构空间。

### 38. 如果要扩展双发射，当前架构哪些部分需要重构？

**答题要点：**

- 需要增加取指带宽、双指令译码、发射约束、寄存器读写端口、功能单元仲裁和成对提交控制。
- 更关键的是同周期 RAW/WAW/WAR、分支、异常和多周期单元的精确定序问题。
- 当前注册化握手、分离控制包和数据包是可复用基础，但并不意味着可直接开启双发射。

## 十、取指、分支预测与控制流追问

### 39. BTB 的组织方式和预测依据是什么？

**答题要点：**

- IF 阶段维护 128 项 BTB，表项包含有效信息、标签、预测目标和 2 bit 饱和计数器。
- 取指 PC 命中标签且计数器高位表示“倾向跳转”时，IF 直接取预测目标。
- 执行阶段获得真实分支结果后更新预测信息；JALR 的目标依赖寄存器值，通常不按普通静态目标直接写入 BTB。

### 40. 为什么使用 2 bit 饱和计数器，而不是 1 bit 预测？

**答题要点：**

- 1 bit 预测会在循环退出时翻转一次、下一次进入循环又翻转一次，容易连续产生两次误判。
- 2 bit 计数器对单次异常分支更稳定，需连续相反结果才切换预测方向。
- 其代价很小，适合五级流水中的轻量动态预测。

### 41. 分支预测错误时具体发生了什么？

**答题要点：**

- EXE 阶段比较预测结果与真实跳转结果 / 目标地址。
- 不一致时向前端发起重定向，并清除预测路径上尚未提交的错误指令。
- 已进入后级且属于正确路径的指令保持，避免“全流水线重置”造成不必要损失。

### 42. `JAL`、`JALR` 和条件分支的处理差异是什么？

**答题要点：**

- 三者都会产生控制流改变和链接地址写回需求，但目标地址来源不同。
- `JAL` 目标由 PC 与立即数确定，条件分支取决于比较结果，`JALR` 还依赖寄存器源操作数。
- 因此对 `JALR` 的预测与恢复要特别注意数据相关和对齐规则。

### 43. 分支密集型 CPI 为何是 1.208？这一结果说明什么？

**答题要点：**

- 分支密集型程序对预测正确率最敏感；预测错误会产生冲刷和重新取指开销。
- 1.208 高于 ALU、访存基准，说明控制相关仍是当前主要剩余瓶颈之一。
- 这不是“预测器无效”，而是证明基准能够暴露可继续优化的方向，例如 BTB 容量、索引、历史信息和目标预测。

### 44. 异常或中断到来时，如何保证不会把预测路径的指令提交？

**答题要点：**

- Trap 事件产生后，对仍处于错误或未决路径的前级指令实施冲刷。
- 写回与外设写操作必须受有效 / 提交控制约束，不能因为已计算出结果就提前产生架构副作用。
- 这也是使用注册化握手和统一 Trap 控制的重要原因。

## 十一、数据相关、访存与时序追问

### 45. EXE、MEM、WB 前递各自解决什么问题？

**答题要点：**

- EXE 前递服务于上一条普通 ALU 指令已经产生的结果。
- MEM、WB 前递覆盖结果在后续级才可用或仍在等待提交的情形。
- 相关检测比较消费者源寄存器与在途生产者目的寄存器，并结合写使能、结果就绪条件和 x0 规则选择前递或停顿。

### 46. 为什么 Load 指令比普通 ALU 指令更难前递？

**答题要点：**

- ALU 结果通常在 EXE 末端产生，而 Load 的数据要经过存储器访问后才有效。
- 若紧邻消费者在 EXE 需要该数据，普通前递路径来不及提供，便形成 load-use 冒险。
- 受控 BRAM 旁路和栈值缓冲正是针对这一路径的局部优化。

### 47. 栈值缓冲命中时，为什么还需要“捕获到前递寄存器”？

**答题要点：**

- 直接把缓冲组合查询结果跨越多个流水级使用，会拉长时序路径并增加控制耦合。
- 命中数据先进入专用寄存器，再在下一条普通整数 ALU 指令中使用，可在性能收益与时序可控之间取得平衡。
- 因此“零空泡”不等于“无寄存器边界”，而是消费者无需额外停顿。

### 48. 栈值缓冲是否可能产生同地址的新旧值竞争？

**答题要点：**

- Store 对命中项进行更新或失效，保证后续 Load 不读到旧副本。
- 对齐全字写可写入完整字数据；部分写由于无法安全重建完整字，主动失效。
- 地址冲突、未命中、非栈地址均退回主 BRAM 路径，因此最坏情况是性能下降而非功能错误。

### 49. 为什么以 `sp/s0` 作为栈访问识别条件？是否有漏判或误判风险？

**答题要点：**

- 这两个寄存器是常见的栈指针 / 帧指针基址，能覆盖典型编译器生成的局部变量访问。
- 仅在地址对齐、访问类型和内存窗口满足条件时启用，宁可保守退回普通路径，也不做不安全推断。
- 若程序用其他寄存器保存栈基址，优化可能不命中，但架构功能不受影响。

### 50. 非对齐访存如何处理？

**答题要点：**

- PPT 中已覆盖取指 / 访存地址非对齐等同步异常。
- 非对齐访问不进入栈值缓冲的受控优化路径，应按规范触发对应 Trap，而不是尝试拼接数据。
- 这样简化内存系统并避免跨字、跨边界带来的复杂一致性问题。

### 51. Store、Load 的字节 / 半字扩展如何保证正确？

**答题要点：**

- Load 需按指令类型完成字节选取及有符号 / 无符号扩展；Store 需生成正确的写使能和字节数据。
- 栈值缓冲只优化对齐全字访问，部分写主动失效，避免与字节写掩码相互矛盾。
- 这类逻辑应通过 LB/LBU/LH/LHU/LW 与 SB/SH/SW 的边界地址和符号扩展用例验证。

### 52. 受控 BRAM 前递为什么不覆盖所有访存指令？

**答题要点：**

- 仅对固定时序、数据来源确定、消费者类型明确的场景开启，可避免把 BRAM 返回路径扩展到分支、Store、CSR 或多周期单元。
- 覆盖范围越大，组合路径、异常交互和验证组合会迅速增加。
- 当前策略用“默认开启但范围受控”的方式，在收益和风险间平衡。

## 十二、CSR、Trap、PLIC 与系统软件追问

### 53. Zicsr 支持的价值是什么？

**答题要点：**

- CSR 是异常中断、性能计数和系统软件运行的状态接口。
- 通过 CSR 可保存 Trap 原因、入口地址、返回地址等关键信息，也可提供 `Cycle`、`Instret` 等性能观测。
- 它使 CPU 从“只能执行指令”扩展为“可被系统软件管理的处理器”。

### 54. Trap 发生后，PC、原因和返回地址如何管理？

**答题要点：**

- Trap 控制记录异常 / 中断原因及发生时的返回 PC，并将取指重定向到 Trap 入口。
- 服务程序处理完成后执行 `mret`，根据保存的返回地址恢复程序流。
- 应强调精确异常原则：异常之前已提交的状态保留，异常之后未提交的指令不得产生副作用。

### 55. 同步异常和异步中断的优先级如何理解？

**答题要点：**

- 同步异常由当前指令执行直接产生，必须与该指令精确对应；异步中断来自外部事件。
- 在同一处理边界出现时，需要由 Trap 控制按明确优先级裁决，通常保证当前同步异常语义不被外部中断掩盖。
- 实际优先级编码和寄存器行为以实现与规范约束为准，答辩时不要虚构未展示的优先级细节。

### 56. Timer 中断、UART 中断和 PLIC 的协作关系是什么？

**答题要点：**

- 外设产生中断请求，PLIC 对外部中断源进行仲裁和投递。
- CPU 响应中断后进入 Trap，软件在 ISR 中读取外设状态、清除或确认中断源，再由 `mret` 返回。
- Timer、UART、PLIC 的模块级 RTL 测试和 SoC / 板级观察共同验证这条链路。

### 57. 为什么 PLIC 是特色功能，而不仅仅是“一个外设”？

**答题要点：**

- PLIC 将多个异步外设事件转换为 CPU 可管理的统一外部中断接口。
- 它将处理器核、CSR/Trap 机制和外设软件驱动连接起来，是从裸核走向可运行系统的重要结构。

### 58. 当前具备怎样的 RT-Thread 移植基础？

**答题要点：**

- 已有 CSR、Timer、中断、UART、PLIC、MMIO 与异常返回等底层条件。
- 这些能力分别支撑时钟节拍、上下文切换相关 Trap、串口输出 / 调试和外设中断。
- 应准确表达为“具备移植与验证基础”；完整移植仍需完成启动代码、时钟、中断、串口、内存布局等适配与实际测试。

### 59. 如果系统软件需要原子操作或用户态隔离，当前设计如何演进？

**答题要点：**

- 原子操作需要扩展 A 指令集及总线 / 存储器的原子语义；用户态隔离需要更完整的特权级与内存保护机制。
- 这些属于在现有机器态、单核 SoC 基础上的明确扩展，不应误称为已具备。
- 当前模块化控制包、CSR/Trap 基础可减少后续接入成本，但仍需专门设计和验证。

## 十三、SoC、存储映射与 FPGA 落地追问

### 60. 自建 SoC 包含哪些模块？各自作用是什么？

**答题要点：**

- SoC 将 CPU 与程序 / 数据存储、UART、Timer、GPIO、PLIC 等通过存储映射方式整合。
- UART 提供输出和调试观测；Timer 支撑时基和中断；GPIO 支撑 LED、数码管等板级可观测交互；PLIC 管理外部中断。
- 该平台的目标是让 CPU 脱离单纯仿真，进入可下载、可运行、可观察的 FPGA 环境。

### 61. MMIO 访问和普通内存访问如何区分？

**答题要点：**

- 根据访问地址所属窗口进行译码：程序 / 数据内存走存储器，外设地址走对应 MMIO 从设备。
- 从 CPU 看都表现为 Load / Store；差异由 SoC 互连、地址译码和外设读写副作用处理。
- 对带副作用的外设寄存器，应避免将其纳入访存优化或重复访问。

### 62. 为什么需要串口、LED、数码管等多种观测手段？

**答题要点：**

- 串口适合输出日志、测试结果和性能数据；LED / 数码管适合在缺少调试器时快速确认 FPGA 是否进入预期状态。
- 多种观测手段降低“仿真通过但板级不可见”的定位难度。
- 板级可观测并不替代 RTL 仿真，而是分层验证的最后一环。

### 63. FPGA 上的频率、资源和时序如何看待？

**答题要点：**

- 频率由综合、布局布线后的关键路径决定；资源由 LUT、FF、BRAM、DSP 等共同构成。
- 本作品的关键设计刻意考虑了 DSP 映射、ROM 映射、注册化握手和受控旁路，以提升时序收敛概率。
- 若评委索要精确数字，应以当前工程的实现报告为准，不能把仿真时钟或设计目标误当为已收敛频率。

### 64. 为什么性能优化可能反而降低最高频率？

**答题要点：**

- 优化 CPI 的旁路、比较和选择逻辑可能增加组合深度、扇出或布线压力。
- 因此应同时看 `IPC / CPI` 与 `Fmax`，最终吞吐更接近二者的乘积，而非单看某一指标。
- 受控优化、寄存器切分和综合后 QoR 对比是避免“局部优化反噬全局”的必要手段。

### 65. 为什么不直接使用软核或厂商处理器 IP？

**答题要点：**

- 使用 IP 可缩短交付时间，但无法体现本作品对微架构、冒险、乘除法、Trap 和性能优化的自主设计能力。
- 自建 CPU 和 SoC 便于针对赛题负载进行可解释优化，并能建立完整的回归和测评流程。
- 项目也可把 IP 作为对照基线，而不是简单的替代方案。

### 66. 程序如何被装载或运行？

**答题要点：**

- 当前验证以裸机程序为主，经程序 / 数据存储映射在 SoC 上运行，并通过 UART 等方式观察结果。
- 工程的具体加载方式、镜像格式、链接地址应以当前构建脚本和板级流程为准。
- 关键是已经形成“编译—加载—运行—串口观测—结果核对”的可重复路径。

## 十四、验证方法、覆盖与可信度追问

### 67. 分层验证与端到端验证分别解决什么问题？

**答题要点：**

- 模块级验证快速定位乘除法、UART、Timer、PLIC 等局部逻辑；CPU / SoC 级验证检查模块互连和指令语义。
- FPGA 板级验证确认综合实现、时钟复位、存储映射和真实 I/O 环境下的可运行性。
- 三层缺一不可：只做模块仿真不能证明系统可运行，只做板级观察也难以定位边界错误。

### 68. 乘法、除法各做了哪些针对性验证？

**答题要点：**

- 乘法覆盖符号边界组合、200 组随机向量、流水冲刷和背压保持。
- 倒数乘除法覆盖 ROM 桶边界、10 万组随机除法对、不同前导零位置、符号边界、除零、溢出、商余数符号和固定延迟，总计 331,279 项检查。
- 这些测试覆盖“数学正确性”和“流水控制正确性”两个层面。

### 69. 随机测试是否足以证明除法完全正确？

**答题要点：**

- 随机测试能发现大量组合错误，但不能替代边界、定向和形式化性质检查。
- 因此除了随机向量，还加入除零、溢出、符号、ROM 边界、归一化位置和延迟等定向覆盖。
- 更进一步可引入参考模型比对、覆盖率统计和形式化验证，这是后续质量提升方向。

### 70. 如何验证栈值缓冲没有改变程序语义？

**答题要点：**

- 对命中、未命中、全字 Store 更新、部分 Store 失效、冲突替换、非栈地址回退等场景进行定向测试。
- 以关闭优化时的功能结果为基线，对比开启优化后寄存器和内存最终状态。
- 性能计数只用于衡量停顿差异，正确性判断必须以 ISA 可见结果一致为标准。

### 71. 如何验证异常和中断不是“能进但回不来”？

**答题要点：**

- 定向触发 `ecall`、`ebreak`、地址非对齐以及 Timer、UART 等中断源。
- 检查 Trap 原因、返回 PC、CSR 状态、ISR 执行以及 `mret` 后是否回到正确程序流。
- 同时观察冲刷后是否存在错误路径写回或重复外设副作用。

### 72. 自动化回归如何组织？改一个模块后如何快速判断影响范围？

**答题要点：**

- 将单元测试、指令测试、冒险测试、异常中断测试、外设测试和性能基准纳入固定脚本或固定执行序列。
- 修改乘法、访存、Trap 等模块后，先跑相关定向测试，再跑全量回归，最后更新性能对比。
- 日志应保存测试名称、通过状态、关键计数和失败上下文，便于复现问题。

### 73. 仿真与 FPGA 结果不一致时，优先从哪里排查？

**答题要点：**

1. 时钟、复位、约束和 CDC；
2. 存储初始化、程序镜像和链接地址；
3. MMIO 地址译码、UART 波特率 / 时钟分频；
4. 综合后 RAM / DSP 推断差异及未初始化寄存器；
5. 通过串口标记、LED、片上逻辑分析等逐层缩小范围。

### 74. 为什么说“回归测试工程”也是作品的一部分？

**答题要点：**

- 处理器功能相互耦合，性能优化很容易引入角落回归；没有回归体系，功能迭代不可持续。
- 自动化测试将设计质量从“一次性演示”提升为“可重复验证的工程过程”。
- 这与竞赛中“能运行”相比，更强调可维护、可复现和可持续优化的能力。

## 十五、性能、对比与数据解读追问

### 75. 你们的 CPI 是如何计算的？是否排除了启动开销？

**答题要点：**

- CPI 由 CSR 读取的周期数与提交指令数计算，即 `Cycle / Instret`。
- 自建分类基准在指定测量区间读数，避免将无关初始化混入核心负载；具体边界以基准程序实现为准。
- 汇报中应同时给出 cycles 与 instret，避免仅报 CPI 而缺失可复核信息。

### 76. 为什么访存密集型 CPI 接近 1，而仍要做 load-use 优化？

**答题要点：**

- 访存密集型基准的指令编排、地址模式和依赖距离不一定集中触发紧邻 load-use。
- 栈值缓冲针对的是实际程序中频繁出现的栈变量依赖热点；`irom-v2` 的 14.96% 周期下降说明此类负载确有收益。
- 不同基准反映不同瓶颈，不能用一个 CPI 数字否定另一类真实场景优化。

### 77. `irom-v2` 的 14.96% 能否写成“CPU 提升 14.96%”？

**答题要点：**

- 不建议这样表述。准确说法是：**在 irom-v2 测试中，周期数下降 14.96%**。
- 该收益与程序栈访问比例、依赖密度和内存访问模式相关。
- 若要给出整体性能结论，需要在多个代表性程序、统一频率和统一编译条件下做几何平均或加权统计。

### 78. CoreMark 为什么不直接给出分数与其他 CPU 对比？

**答题要点：**

- CoreMark 分数依赖时钟、编译器版本、优化选项、内存位置、运行次数和计时实现；不统一条件的横向比较没有意义。
- 当前已完成裸机运行验证并建立分类基准，优先证明测评路径可靠。
- 后续可在固定 FPGA、固定频率和公开编译配置下补充可复现的 CoreMark / MHz 或 CoreMark 分数。

### 79. 怎样衡量“性能优化是否值得”？

**答题要点：**

- 同时记录周期数、CPI、关键停顿计数、Fmax / 时序裕量和 LUT / FF / BRAM / DSP 资源变化。
- 若 CPI 改善但 Fmax 明显下降，则需要用实际吞吐比较是否仍有正收益。
- 还需评估优化是否扩大控制复杂度和验证成本；栈值缓冲采用受控范围正是该取舍的体现。

### 80. 你们选择的对比基线是什么？

**答题要点：**

- 性能优化的直接基线应是“关闭相应优化、其余条件相同”的同一 RTL / 同一程序版本。
- 对外部软核、IP 或其他 RISC-V 核的比较，需要统一 FPGA、频率、存储、编译器和测试集，不能只摘取宣传数字。

## 十六、工程取舍、风险与开放式问题

### 81. 项目中最难的部分是什么？

**答题要点：**

- 可选择“多周期精确除法接入流水线”或“访存优化下的正确性边界”作为回答重点。
- 难点不只在算法，还在请求握手、冲刷、背压、异常交互和回归验证。
- 结论应落到：通过明确边界、分层验证和自动化回归，将复杂功能变成可控工程模块。

### 82. 如果再给一个月，会优先做什么？

**答题要点：**

- 优先顺序建议为：完成 RT-Thread 实际移植和测评；扩大基准集并输出统一性能报告；继续优化分支预测与访存路径。
- 在功能基线稳定后，再研究 Cache、AXI 或更宽的发射能力。
- 这样回答体现“先验证和量化，再扩大复杂度”的工程节奏。

### 83. 该设计有哪些已知局限？

**答题要点：**

- 当前为单发射、五级流水、RV32 处理器；未以通用 Cache、双发射、完整特权体系或多核为目标。
- 栈值缓冲只优化特定热点，不能替代通用存储层次结构。
- RT-Thread 为移植基础而非已完成的官方测评成果。主动说明边界比泛化宣传更可信。

### 84. 如何确保“优化开关”不会形成两套难以维护的 CPU？

**答题要点：**

- 优化模块应保持对外 ISA 语义不变，并通过统一接口与流水线连接。
- 基线模式和优化模式都应进入回归；重点测试同一程序的最终状态一致性。
- 优化范围受控、回退路径明确，可以避免开关演变成不可验证的分叉实现。

### 85. 如何从教学 / 竞赛作品演进到更接近工业原型？

**答题要点：**

- 先补齐可追溯需求、接口规格、覆盖率、实现报告和性能报告。
- 再完善系统软件、总线、存储层次、调试接口、低功耗 / 时钟复位和异常处理覆盖。
- 工业化的关键不只是“更多功能”，而是设计、验证、实现和软件之间都有可复现证据链。

### 86. 团队三名成员如何协作，如何保证工作可复现？

**答题要点：**

- 可按实际分工回答，例如 CPU 核心与执行单元、SoC / 外设与板级、验证 / 基准与文档；必须与真实分工一致。
- 公共工程通过版本管理、统一脚本、固定测试入口和日志归档协作，避免只在个人环境中可运行。
- 评委若继续追问，应准备各成员可独立讲清的模块、测试和实际贡献。

### 87. 如果评委要求现场展示，你们展示什么最有说服力？

**答题要点：**

1. FPGA 上电后的串口启动与裸机测试输出；
2. 一组可识别的乘除法、异常或中断演示；
3. 优化开关前后的 `irom-v2` 周期对比；
4. 自动化回归日志中的通过结果和 CPI 汇总。

### 88. 面对不确定的参数问题，怎样回答才专业？

**答题要点：**

- 先说明已确认的设计事实，例如“普通除法 14 拍”“BTB 为 128 项”“栈缓冲为 16 项”。
- 对资源、后仿频率、功耗等依赖当前工具版本的值，明确回答“以当前实现报告为准”，随后展示或补充报告。
- 不猜测、不夸大、不把设计目标、仿真设置或历史版本结果混为一谈。

## 十七、可用于模拟答辩的追问链

下面几组问题建议由队内成员连续演练，因为评委往往会沿着一个结论逐层追问。

### 追问链 A：栈值缓冲的真实性

1. 为什么要做栈值缓冲？
2. 为什么不是通用 Cache？
3. Store 后怎样保证一致性？
4. 部分写为什么失效而不是更新？
5. 16 项够不够？冲突如何处理？
6. 14.96% 是什么条件下得到的？
7. CPI 与 Fmax 是否同时改善？

**核心落点：** 该结构以主 BRAM 为准、范围受控、优化热点、结果可测，并主动承认收益与负载相关。

### 追问链 B：倒数乘精确除法

1. 为什么不用逐位除法或 IP？
2. ROM 的精度和容量为何这样选？
3. 一次迭代怎样保证精确？
4. 除零、溢出、符号、余数如何处理？
5. 为什么是 14 拍？
6. 多周期结果如何避免被异常 / 分支冲刷后错误写回？
7. 如何验证算法与控制都正确？

**核心落点：** 近似只用于加速，最终余数检查和商校正保证 ISA 精确语义；接口控制和大规模定向 / 随机测试保证其可安全接入流水线。

### 追问链 C：性能与工程价值

1. CPI 1.046 是怎样测得的？
2. 为什么 ALU 为 1.000、分支为 1.208？
3. 为什么不直接给 CoreMark 分数？
4. 优化是否会牺牲频率？
5. 如何证明不是只对一个程序有效？
6. 与 IP / 软核相比的价值是什么？
7. 下一步最先验证什么？

**核心落点：** 当前已有可复现的测评基础和特定负载实测，不夸大为通用结论；下一步将统一条件扩大基准与系统软件验证。
