UART 在 PL Bank34，原理图 `PS_UART_*` 只是网名；无需 PS MIO/EMIO。主机此前为 COM6，CH340 VID/PID `1A86:7523`，115200/8N1/无流控，重插后重新枚举。唯一 JTAG 目标曾为 `localhost:3121/xilinx_tcf/Digilent/<序列号>`；每次 Program 都重新检查。正确 DONE 属性为 `REGISTER.CONFIG_STATUS.BIT13_DONE_INTERNAL_SIGNAL_STATUS` 和 `REGISTER.CONFIG_STATUS.BIT14_DONE_PIN`，旧缩写 `BIT13_DONE` 不存在。

SoC 普通 reset PC=`0x80000000`，指令 ROM 16 KiB；数据 RAM=`0x80100000..0x8013FFFF`，256 KiB，栈顶=`0x80140000`。UART/Timer/LED 基址依次为 `0x80010000/0x80020000/0x80030000`，PLIC 在 `0x8030xxxx`。编译为 `rv32im_zicsr/ilp32`，不能用 xPack 默认 `rv32imac` 引入未实现 A/C。UART 使用内部 CPU 时钟分频，CTRL=`0x14`；50 MHz BAUD=`433`，160 MHz BAUD=`1388`。

## 构建、恢复、下载和采集

以下从 `W:\riscv-cpu-refactored` 的 PowerShell 7 运行。每次选择全新输出目录；示例中的 `new_*` 是待生成目录，不代表已有证据。`Gen` 只生成固件和配置，`Build` 生成独立 Vivado 工程/报告/bit。本机旧 npm PATH 联接曾使 Vivado 崩溃，入口已仅对子进程采用最小 PATH；不需修改全局 PATH。

```powershell
# 新建50 MHz smoke：编译、检查镜像、综合、实现与写bit
pwsh -File scripts/run_board.ps1 -Mode Build -App smoke -CpuHz 50000000 -Iterations 0 -BuildDir W:\riscv-cpu-refactored\build\hello_zynq\new_smoke50

# 新建100 MHz正式CoreMark，iterations=0由固件校准到至少10秒
pwsh -File scripts/run_board.ps1 -Mode Build -App coremark -CpuHz 100000000 -Iterations 0 -BuildDir W:\riscv-cpu-refactored\build\hello_zynq\new_core100

# 仅构建固件：inst.mem/data.mem、ELF、dump、COE和manifest
python scripts/build_board_firmware.py --app coremark --cpu-hz 100000000 --iterations 0 --output W:\riscv-cpu-refactored\build\hello_zynq\new_firmware100

# 已完成route但只在报告/写bit阶段失败时复用，不重跑综合/实现
pwsh -File scripts/run_board.ps1 -Mode Finish -BuildDir <已有构建目录>

# 在一个终端先开被动采集；output必须是新目录，等待CAPTURE_READY
& <serial-python> scripts/board_capture.py --port COM6 --baud 115200 --duration 180 --cpu-hz 100000000 --require-valid-coremark --output W:\riscv-cpu-refactored\build\hello_zynq\new_capture100

# 另一个终端再加载已检查的bit（会改变板上易失配置）
pwsh -File scripts/run_board.ps1 -Mode Program -BuildDir <已有100MHz构建目录>
```

`Program` 依据 `build_summary.json` 校验 bit SHA-256、DRC 和唯一目标，然后检查 DONE、要求 `BOARD_PROGRAM_SUCCESS`。160 MHz 等 STA 未收敛点必须显式加 `-AllowTimingFailure`，不能把它写成基线 PASS。`Finish` 只容许两份报告脚本变化；RTL/XDC/镜像变化需新建完整构建，不要删除快照或绕过检查。采集器只收字节不发串口命令；遇 CoreMark 结果会独立复算，不够 10 秒为 SHORT。不要将 smoke程序不存在的 PING/ECHO 协议套过来。

频率扫描入口 `scripts/run_frequency_campaign.py` 默认每点独立构建、先采集后下载，`--confirm-failure` 对首次失败再试一次。仅查看计划、不触硬件可用：

```powershell
python scripts/run_frequency_campaign.py --start-mhz 60 --step-mhz 10 --max-mhz 170 --iterations 0 --root-output W:\riscv-cpu-refactored\build\hello_zynq\new_campaign --plan-only
```

当前已测固件 builder 限制最高 **200 MHz**，而 campaign 参数默认最高为 400 MHz。重新运行时应显式设置 `--max-mhz` 不超过 200；超出会被 builder 拦截，属于 `TOOL_BLOCKED`，不是实板频率失败。为保持已测源码哈希，收尾未改这两处限制。

## STA、CDC及结果边界

50 MHz CoreMark WNS=`+5.950 ns`、WHS=`+0.060 ns`，成绩 `107.415435`。160 MHz WNS=`−2.449 ns`、TNS=`−6463.526 ns`、WHS=`+0.062 ns`、THS=0；失败端点包括5,511个CPU setup和671个reset recovery，最差 EX 结果路径 `ds_to_es_bus_r_reg[5]` → `skid_exe_result_reg[25]`，以及板级复位扇出。170 MHz WNS=`−2.984 ns`、WHS=`+0.050 ns`；不能说hold失败。

160 MHz全SoC资源：LUT 6,723、FF 5,368、BRAM36 68/140、DSP 4/220。DRC严重项为0仍有33条Warning；CDC为 **CDC-7 Critical 12条、CDC-2 Warning 1条、CDC-9 Info 1条**，涉及复位异步端和UART同步链属性。没有通过全CDC签收；不要用“DRC严重项0”写成所有检查全绿。默认活动功耗估计不是实测功耗。
