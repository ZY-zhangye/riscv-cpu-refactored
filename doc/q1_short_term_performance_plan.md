# Q1 后续短期性能计划

## 当前基线

当前分支 `codex/multi-issue-inorder` 固定在 Q1 提交 `eabb47e`。Q1 是 125 MHz 提交基线：

```text
cycles  = 1,751,323
instret = 2,279,454
IPC     = 1.301
```

当前配置保持 2-wide 顺序多发、4-entry issue queue、双执行 lane、128-entry BTB、2-bit 方向预测、JALR BTB 和 8-depth RAS。

Q1 默认允许独立简单整数与 M 指令同包启动，但关闭完整同周期 ALU 旁路。云端普通 125 MHz 实现的 setup WNS 为 `+0.292 ns`，因此 Q1 是当前唯一应优先保护的发布回退点。

## 本阶段明确不做

短期窗口只有约 3~4 天，且之后需要进行流水线拆分。因此本阶段不引入：

- ROB、物理寄存器、寄存器重命名或 rename checkpoint；
- 通用 oldest-ready issue window；
- 乱序访存、store queue 或推测性 load；
- 多个未完成 M 操作；
- 完整同周期跨 ALU 旁路；
- 需要改变提交顺序或异常恢复边界的结构。

所有实验必须通过独立编译宏保留 Q1 回退路径，不能直接覆盖默认配置。

## 候选一：受限控制流双发

第一版只允许：

1. lane0 为普通非控制流指令；
2. lane1 为一条控制流指令；
3. 一个 bundle 内最多一条控制流；
4. 不允许控制流位于 lane0 后再带年轻 lane1；
5. 不放开控制流与 store、CSR 或其他不可回滚副作用的任意组合。

控制流配对必须在 issue 配对阶段决定。EX 末尾只负责 redirect 优先级和清理后续 fetch/issue 内容，不能在那里补救已经发生的年轻副作用。

验收重点：taken/not-taken、JAL/JALR、误预测恢复、lane1 控制流写回和异常测试。若收益只有少量周期，保留为实验宏，不进入默认 Q1。

## 候选二：有限 M 阻塞绕过

这是本阶段最值得优先验证的结构。允许老的 M 指令启动后，年轻的独立简单 ALU 使用空闲整数执行资源继续发射，但规则必须限制为：

- 老指令只能是 MUL/DIV；
- 年轻指令只能是简单整数 ALU；
- 年轻指令的源寄存器不能依赖老指令目的寄存器；
- 年轻指令不能写老指令目的寄存器；
- 年轻指令不能是 LSU、CSR、控制流或可能改变异常状态的指令；
- 同时最多一个 M 操作在飞。

这不是通用乱序执行。M 仍按原顺序启动和完成，年轻 ALU 只在确定独立且不会产生 WAW 的情况下使用空闲资源。若当前 queue 结构无法支持该特判，应增加一个最小的 M/ALU 选择路径，不要扩展成通用 oldest-ready 仲裁器。

验收重点：M 依赖、M 后独立 ALU、M 后同目的寄存器、分支恢复、异常和完整 benchmark sink。优先比较 MEXT 窗口 cycles 与总 IPC。

## 候选三：受限同包 WAW

该项预期收益最低，只有前两项完成后才考虑。建议只允许两条简单整数 ALU 同包写同一个非零 `rd`，并定义 lane1 结果为最终架构结果。禁止 LSU、CSR、控制流、M 和异常相关指令参与；同包不能再读取该目的寄存器。

已有候选测试表明，放开同包 WAW 对 cycles 没有实际收益。因此除非新的动态计数证明 WAW 是主要阻塞，否则不进入默认配置。

## 实施和停止条件

每个候选都必须：

1. 使用独立宏和独立提交；
2. 先通过定向 issue、分支、M、访存和异常测试；
3. 再运行完整性能 benchmark，确认 sink、exceptions、cycles、instret 和 IPC；
4. 与 Q1 比较 `IPC`，并记录新增的配对、RAW、WAW、结构和 redirect 事件；
5. 在云端可用时再综合，比较 WNS/TNS、资源和 `IPC × Fmax`。

出现以下任一情况立即停止该候选：

- 正确性需要回滚已执行的年轻副作用；
- 需要跨周期保存任意完成顺序或恢复状态；
- 需要修改 ROB/重命名接口；
- IPC 收益小于约 1%，或时序导致 `IPC × Fmax` 下降；
- 代码开始需要通用窗口、tag 网络或多端口结果广播。

## 后续流水线拆分

本阶段的 issue 规则实验完成后，下一主线再统一处理流水线拆分。拆分目标是隔离：

- issue queue 配对和 CE/D 控制；
- ALU 结果到 lane1 的组合选择；
- M 请求/完成握手；
- CPU 到 DRAM BRAM 的 WEA 控制路径。

流水线拆分前保留 Q1、所有通过的局部候选以及完整 benchmark 结果，统一以 `IPC × Fmax` 选择最终提交版本。

## 分支管理

Q1 分支 `codex/multi-issue-inorder` 只保留稳定基线。任何新实验使用独立分支和宏；实验失败时直接丢弃分支，不回写 Q1。已完成的 A 系列 ROB/window 实验保存在本地 `codex/a-series-rob-experiment`，不再作为近期优化主线。
