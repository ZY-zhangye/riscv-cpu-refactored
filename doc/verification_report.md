# RV32 RISC-V CPU 功能验证报告（草案）

## 1. 报告目的与版本范围

本报告说明本项目 RV32 RISC-V CPU 及 SoC 外设的功能验证方法、已有结果和待补测项，为竞业达杯提交材料中的“验证报告”提供可直接扩展的正文基础。

本报告依据工作区于 2026-07-16 可见的 RTL、测试平台和结果日志编写。当前工程仍处于性能优化阶段，因此本报告不将某个未提交工作区状态固化为最终发布版本；提交前应在候选 RTL 定版后重新执行第 5 节回归并更新日志时间、提交号和结果表。

## 2. 验证目标

验证覆盖以下四个层次：

1. **指令集功能**：验证 RV32I 基础整数指令、机器态/CSR 相关指令和 RV32M 乘除法指令的执行结果。
2. **流水线控制**：验证取指同步与分支预测、数据相关处理、乘除法流水控制以及异常/冲刷等关键控制路径。
3. **SoC 外设功能**：验证 UART、定时器、PLIC 和存储器映射访问的寄存器语义及中断协同。
4. **系统级软件执行**：通过裸机 C 程序和性能基准验证从程序镜像、取指、访存到串口/邮箱输出的完整链路。

## 3. 验证环境与方法

### 3.1 验证环境

| 项目 | 配置 |
|---|---|
| RTL 描述语言 | SystemVerilog |
| 仿真器 | Questa Sim 2024.1（由结果日志记录） |
| 处理器测试平台 | `test/tb_my_cpu.sv`、`test/tb_cpu_top.sv` |
| SoC/性能测试平台 | `test/tb_top.sv` |
| 指令镜像 | `hex/riscv-tests/` 下的 RISC-V 测试镜像 |
| 回归入口 | `run_all.bat` |

### 3.2 分层验证流程

```text
模块定向测试
    ↓
ISA 指令回归（tb_my_cpu）
    ↓
CPU/SoC 集成仿真
    ↓
裸机程序与性能基准（tb_top）
    ↓
FPGA 板级运行与串口/LED 观测
```

回归脚本对每一条 ISA 测试镜像启动仿真，并在对应结果文件中检索 `Test passed.`。任何一个用例未出现该标记时，脚本以失败返回，避免将编译成功误判为功能通过。

## 5. 已有验证结果

### 5.1 ISA 回归结果

截至本报告整理时，`results/` 目录中保留了 49 份可检索到 `Test passed.` 的 ISA 结果文件，统计如下。

| 类别 | 通过数 | 结论 |
|---|---:|---|
| RV32UI | 37 / 37 | 通过 |
| RV32MI | 4 / 4 | 通过 |
| RV32UM | 8 / 8 | 通过 |
| 合计 | **49 / 49** | 通过 |

该结果表证明当前保留的回归结果中，基础整数、机器态/CSR 相关和 M 扩展测试均达到脚本定义的通过条件。该统计不替代定版后的全量回归；尤其是 Z 扩展和新增优化模块必须在 RTL 冻结后重新执行并归档。

### 5.2 系统级软件执行

性能基准测试通过 `test/tb_top.sv` 启动裸机镜像并读取数据 RAM 邮箱中的周期、退休指令等结果。最新日志 `results/perf_bench.log` 的结束标记为 `[PERF] PASS`，表明镜像构建、RTL 编译、SoC 仿真、结果读取与 `sink` 校验均完成。

### 5.3 板级与论文阶段证据

毕业论文材料中保留了 UART、Timer、PLIC 仿真截图、开发板连接照片、串口测试截图和 CoreMark 运行截图。这些材料适合作为板级验证的图示证据；竞赛提交前应重新采集与当前 RTL 对应的实验箱照片、串口日志和演示视频，避免论文阶段图像与当前优化版本不一致。

## 6. 待补测与提交前检查清单

1. 固定候选 RTL 版本，并记录 Git 提交号、工具版本、测试日期和 FPGA 目标器件。
2. 执行 `run_all.bat all`，归档 RV32I、机器态、M 与已实现 Z 扩展全部结果。
3. 分别运行 UART、Timer、PLIC、BTB、load-use、乘法、除法和栈值缓冲定向测试，保存控制台日志。
4. 对异常、中断嵌套、分支预测失败、访存冲突和优化模块旁路条件补充波形截图。
5. 在竞赛实验箱上复测官方程序，保留下载步骤、串口输出、结果文件和现场演示视频。
6. 若优化引入性能变化，执行功能回归后再纳入测评报告；功能未回归的性能数据不得作为最终结果。
