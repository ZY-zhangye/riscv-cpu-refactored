# 顺序多发 L3H 128 项 BTB 容量检查点

## 背景与目标

L3G 的 16/64 项 A/B 在原六窗口 benchmark 中完全相同，因此当时只能得出“该微基准未暴露容量瓶颈”，不能推广为真实程序不需要更大 BTB。根据既有真实版本的实测经验，实际负载建议采用约 128 项。

L3H 增加专门的 BTB 容量压力窗口，用 128 个连续静态 taken 分支覆盖全部低位索引，并重复执行 512 轮。每个分支目标为下一条指令，仍会参与方向/目标校验并在未命中时产生恢复气泡。这样可以直接观察小型直接映射表的 tag 冲突，而不依赖编译器偶然生成足够多的分支点。

完成日期：2026-07-11

## 基准扩展

性能邮箱升级为 `L3H0`、version 3，增加 `BRANCH_CAPACITY`，共七个独立测量窗口。邮箱仍位于 `0x6000_0800`，大小由 496 bytes 增至 576 bytes；DATA 链接范围扩到 `0xC00`，仍在 4 KiB data RAM 内。

生成镜像中的 `bench_branch_capacity` 位于 `0x8000_0224`，静态反汇编确认存在 128 条连续 `beqz zero`，分支 PC 每次增加 4 bytes，因此可以完整使用 7-bit BTB 索引，而不是只覆盖偶数索引。

所有 A/B 配置均满足：

- `sink=0x5614D1AB`；
- 七窗口 exceptions=0；
- PC 保持在 `0x8000_xxxx`；
- benchmark 通过。

## 16/128 项 A/B

两种配置均使用 L3G 已签核的 2-bit 方向计数和 JALR 预测。

| 配置 | CAPACITY cycles | CAPACITY mispredict | CAPACITY IPC | 总 cycles | 总 IPC |
| --- | ---: | ---: | ---: | ---: | ---: |
| 16 项 | 331,790 | 66,048 / 66,049 | 0.208 | 1,388,851 | 1.055 |
| 128 项 | 72,202 | 1,151 / 66,049 | 0.957 | 1,129,263 | 1.297 |

128 项使容量窗口：

- 误预测减少 64,897 次，降低约 98.26%；
- cycles 减少 259,588，降低约 78.24%；
- IPC 从 0.208 提高到 0.957。

包含容量压力窗口后，总 cycles 降低约 18.69%，总 IPC 提高约 22.99%。原有 ALU、随机分支、规则分支、短循环、函数调用和 MEMORY 六个窗口的 cycles 与误预测数逐项完全一致，说明扩容没有改变其功能或测量行为，收益只来自原 benchmark 未覆盖的容量冲突。

## 实现与风险

稳定 RTL 现在默认采用 128 项；定义 `L3H_BTB_16_ENTRIES` 可回退到 16 项以复现 A/B。128 项仍为直接映射、双组合查询、单更新口，没有增加相联比较或 EX 数据通路。

表项从 16 扩至 128 后，valid、2-bit counter、tag 和 32-bit target 的原始状态位约增加 6.5 Kbit。当前数组带逐项复位且使用异步读取，综合工具可能以 FF/LUT 而不是 BRAM 实现；同时 128:1 查询选择和较宽复位/更新网络可能影响 IF 的 next-PC 路径。因此仿真收益明确，但在 post-route 双频签核前不能取代 L3G 的正式时序基线。

## 验证

- 16 项 A/B 配置：RTL/testbench 编译 Errors 0、Warnings 0；L3H benchmark 通过。
- 128 项默认配置：RTL/testbench 编译 Errors 0、Warnings 0；`tb_issue_stage`、`tb_multi_issue_l2`、`tb_multi_issue_l3` 和 L3H benchmark 全部通过。
- L3 微基准保持 27 cycles、34 instret、IPC 1.259，没有因 BTB 容量变化产生功能或固定测试回退。
- Questa divider 初始化仍有两条既有除零警告，不影响结果。

## 决策与下一步

1. 接受真实版本经验对 benchmark 覆盖不足的修正，不再以 L3G 的 64 项无变化否定 BTB 扩容。
2. 128 项作为 L3H 默认综合候选；16 项仅保留为回退宏和已签核基线。
3. 下一步在云端先跑 125 MHz 稳健档，再跑 130 MHz 性能档，同时记录 LUT、FF、关键路径簇和预测器数组的实现类型。
4. 若 130 MHz 通过且资源可接受，128 项转为正式基线；若 130 MHz 失败但 125 MHz 通过，应比较 `IPC × Fmax` 后再决策，不直接降频签核。
5. 返回地址栈和分支恢复气泡实验延后到 128 项容量方案完成时序签核之后，避免同时引入多个前端变量。
