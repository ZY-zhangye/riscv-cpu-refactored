# RV32 RISC-V CPU 性能测评报告（草案）

## 1. 测评目的与结论边界

本报告记录当前 RV32 RISC-V CPU 的性能测评方法、最新仿真结果和后续官方测评计划。测评目的不是只给出单一分数，而是分别观察计算密集、分支密集和访存密集负载下的周期数、退休指令数与 CPI，从而为流水线、分支预测和存储系统优化提供依据。

本报告中的“当前结果”来自自建 RTL 仿真基准，不等同于竞业达杯官方工业应用程序或 RT-Thread 测评结果。官方程序、实验箱频率和 RT-Thread 结果应在竞赛环境确定后单独补入第 7 节，不能与本报告的自建基准混合比较。

## 2. 测评对象与环境

| 项目 | 当前配置 |
|---|---|
| 测评对象 | 五级流水 RV32 RISC-V CPU 及其 SoC 封装 |
| 测评程序 | `riscv_sim_perf_bench/benchmark.c` 生成的裸机镜像 |
| 负载类型 | ALU、BRANCH、MEMORY、OVERALL |
| 统计信息 | `cycles`、`instret`、`CPI(x1000)`、`sink` |
| 镜像构建 | RISC-V GCC 交叉编译工具链 |

| 最近一次日志 | `results/perf_bench.log`，2026-07-16 20:50:48 |

基准程序通过 CSR/邮箱机制输出计数器结果；testbench 同时校验 `sink`，用于防止因错误执行或编译器删减导致的“虚假性能提升”。

## 3. 基准负载设计

| 负载 | 主要操作 | 评估目的 |
|---|---|---|
| ALU | 移位、异或、加法等整数运算 | 观察基础流水吞吐与数据通路开销 |
| BRANCH | 条件分支与不同控制路径 | 观察分支预测、重定向和冲刷代价 |
| MEMORY | 数组读写与访存扰动 | 观察访存路径、load-use 冒险与数据相关处理 |
| OVERALL | 三类负载的综合执行 | 作为当前自建基准的汇总口径 |

`riscv_sim_perf_bench/README.md` 说明了基准规模与构建过程；在提交最终数据时，必须固定 `BENCH_SCALE` 和各循环次数，随报告一并给出编译选项与镜像校验值。

## 4. 统计方法

定义：

```text
CPI = cycles / instret
CPI(x1000) = round(1000 × cycles / instret)
```

其中 `cycles` 与 `instret` 由被测 CPU 的性能计数器给出。除 CPI 外，项目还具备分支、分支失预测、load-use 停顿、执行停顿和异常等计数能力；最终报告应在优化对比表中增加这些指标，以解释周期变化的来源。

## 5. 当前 RTL 仿真结果

最近一次自建性能基准的结果如下。

| 负载 | cycles | instret | CPI(x1000) | CPI |
|---|---:|---:|---:|---:|
| ALU | 216,022 | 216,011 | 1,000 | 1.000 |
| BRANCH | 274,402 | 227,026 | 1,208 | 1.208 |
| MEMORY | 601,795 | 600,869 | 1,001 | 1.001 |
| OVERALL | **1,092,219** | **1,043,906** | **1,046** | **1.046** |

结果日志给出的 `sink` 为 `f5b4d4ae`，并以 `[PERF] PASS` 结束。ALU 与 MEMORY 负载接近单周期吞吐；BRANCH 负载的 CPI 较高，符合控制流改变、预测失败恢复和冲刷流水线带来额外周期的预期。该结论仅用于指导当前微架构优化，不应外推为不同程序或不同频率下的普适性能结论。

### 5.1 当前结果的使用限制

- 日志中存在仿真器关于除法运算的 `Infinity results from division operation` 警告；该次基准仍通过 `sink` 与 `[PERF] PASS` 校验。最终提交前应确认该警告对基准路径无功能影响，或消除其根因。
- 不同优化版本若改变了程序镜像、循环规模或退休指令数，不能只比较总周期。应统一镜像与统计口径后再计算加速比。
- 当前日志未提供 FPGA post-route 频率、资源占用、功耗和官方程序结果，因此不将其写为最终硬件性能结论。

## 7. 竞赛正式测评计划

### 7.1 官方工业程序

1. 在组委会提供的实验箱和指定工具链中构建官方程序。
2. 固定 CPU 配置、频率、存储器与编译选项；记录镜像校验值。
3. 对每个程序采集完整串口输出、周期数、退休指令数和性能事件计数。
4. 至少重复三次；若结果有波动，报告均值、最大值和最小值。
5. 对基线与优化版本使用相同程序和相同计数口径，计算加速比。

### 7.2 RT-Thread

| 阶段 | 验收内容 |
|---|---|
| 启动 | 时钟、中断、串口、内存映射与启动代码正确 |
| 系统运行 | Shell/任务调度/定时器等基础功能可用 |
| 基准执行 | 官方指定或可复现的 RT-Thread 工作负载运行完成 |
| 性能统计 | 时间、周期、吞吐与资源占用按统一口径记录 |
| 现场演示 | 新测评程序能够在实验箱上重新编译并执行 |
